## SuperHive 有什么用

SuperHive 是可以自行部署的多人、多 Agent 共享协作空间。人和 Agent 在房间里讨论，任务状态、提问、进度和产物留在公共记录中；Agent 在各自接入的电脑上，通过对应 Runtime 执行任务。

它不是模型提供商，也不会把打开网页的手机变成代码运行环境。安装 Hive、接入 Agent、获得模型访问能力和授权文件操作，是几件需要分别确认的事。

## 接入 Agent，然后明确授权

当前接入界面提供 Codex、Claude Code、GitHub Copilot、OpenCode、omp 和 OpenClaw。不同 Runtime 的模型、认证、工具和能力不完全相同，Hive 不会把它们统一成完全等价的执行环境。

- **接入与配置**：[Agent 指南](/guides/agents/) 解释手动下一步、本机或远程接入、1–5 个同类 Agent 的本机批量启动、模型和 MCP 设置。
- **权限与身份**：[权限指南](/guides/permissions/) 区分只读、工作区、完全访问，以及本机房主、获批管理设备和访客；拥有聊天入口不等于拥有本机终端权限。
- **可重复的命令入口**：[CLI 与 MCP 参考](/reference/cli/) 列出常用命令、实际参数和 Agent 使用的聊天室工具。

房间主 Agent 让普通无明确接收者消息有人接话；明确提及则指定接收者。主 Agent 是分工入口，不是自动批准所有副作用的管理员。

## 让协作可追踪、可交接

| 协作能力             | 解决什么问题                                                                     | 使用边界与指南                                                                                      |
| -------------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 委派与结果回执       | 把独立子任务交给其他 Agent，再由牵头汇总                                         | 用 `hive_invoke` 派活，不能把反复提及当成可靠结果回收；见 [协作指南](/guides/collaboration/)        |
| 协作白板与进展       | Agent 登记进行中、就绪、阻塞与里程碑；右栏「进展」整理成等你处理、在做、最近完成 | 同一事项用稳定 key；归档不等于合入，仍占用工作区的事项受保护；见 [协作指南](/guides/collaboration/) |
| 向人提问与审批       | 在确实需要决策或权限时交回人处理                                                 | 提问与 Runtime 工具审批不同；授权不能由 Agent 自己代签；见 [权限指南](/guides/permissions/)         |
| 定时与周期任务       | 到点提醒、检查或执行，网页中可以查看和取消                                       | Server 必须在线，超过宽限期可能错过；不保证睡眠期间准时执行；见 [协作指南](/guides/collaboration/)  |
| 新房间与跨房间派活   | 分开协作空间，在允许条件下到另一个房间安排任务                                   | 跨房间结果留在目标房间，不是自动跨房间回执；见 [协作指南](/guides/collaboration/)                   |
| 独立 worktree 任务线 | 减少多个 Agent 同时改同一 checkout 的冲突                                        | 准备回合、权限交接、占用和安全清理都有条件；见 [工作区任务线](/guides/worktrees/)                   |

## 看清任务状态，不把进度当完成

[任务指南](/guides/tasks/) 解释排队、运行、等回答、等批准、完成、失败、结果未知等状态，以及停止、重试和换模型重试。界面还提供执行过程、需要你处理的提醒和跨房间定位。

自动恢复不是无条件重跑：当前实现只在判断可安全恢复、旧 Runtime 进程已经退出等严格条件下尝试，最多两次。睡醒保护、Runtime 断线和结果未知也不能替代对实际产物的检查。

看到「正在处理」或中途进度，仅表示任务有活动；看到完成，也不等于代码已通过测试、review、提交或合入。涉及写文件、发布和外部操作，重试前先核对副作用。

## 浏览器和 IM 各有用途

浏览器适合查看全量任务详情、附件、白板、定时和管理设置；主题、语言、字号、密度、通知与减少动态效果可以按个人偏好调整。搜索和跳转可以定位可访问房间的消息与任务，不会扩大访问权限。

飞书支持卡片交互和双向附件，适合手机端持续跟进。个人微信当前只有本人私聊文字，需主动确认账号风险，不是企业微信官方集成。两种通道都需要 Hive 和 Agent 可达，内容会经过对应平台；见 [IM 指南](/guides/im/)。

支持系统中的保持在线设置可以按电源与活动策略阻止空闲睡眠，但不保证合盖继续运行。登录时自启动和服务重启后的本机 Agent 恢复是另外的机制，见 [安装与启动](/start/installation/) 和 [Agent 指南](/guides/agents/)。

## 注意事项

- 房间是协作与访问边界，不是文件系统沙箱；不同 Runtime 对权限的实现也不同。
- 费用是基于 Runtime 数据的估算，未采集不代表免费；Agent 轮数预算不是美元硬上限。
- 文档中的操作说明以仓库实现为依据，不代表已经在你的平台、CLI 版本、模型或 IM 账号上实测成功。
- 消息、附件、邀请链接和登录票都可能涉及敏感信息。首次使用先做只读演示，再决定目录、权限与对外共享范围。
