## 有什么用

用一个房间、一个只读 Agent，确认「你发消息 → Agent 接到任务 → 回复出现在房间」这条链路走得通。不需要真实项目、私人文件或写入权限，也不用一次开好几个 Agent。

开始之前准备两样东西：

- **SuperHive**：有两种方式都可以使用 SuperHive，装法任选一种：
  - **[安装客户端](/start/installation/#安装客户端)**：下载桌面应用，双击打开就在本机启动 Hive，自带终端，不用敲命令。
  - **[安装 CLI](/start/installation/#安装-cli)**：用 npm 装命令行工具 `hive`，适合服务器、Linux、局域网共享或习惯终端的人。

  两种装法用的是同一份数据目录 `~/.superhive/`，可以随时换着用。

- **一个 Agent CLI**：例如 Claude Code 或 Codex，在这台电脑上装好并登录。SuperHive 负责把它接进房间，目前不自带 Agent。

下面按客户端来讲；用 CLI 的话，运行 `hive` 后会自动在浏览器里打开同样的界面，后面的操作完全一样。

## 第一步：打开 SuperHive，建一个练习房间

1. 双击打开 SuperHive。第一次打开会弹出「进入 SuperHive」，填一个你的用户名。在这台电脑上打开的就是房主。
2. 在左侧新建一个练习用的房间，例如「上手演示」。
3. 先不要给房间挂真实项目目录，也不要上传私人资料。以后要处理文件，再在「管理房间」里选一个专用的工作目录。

想让别的电脑上的人一起用，见 [房间与成员](/guides/rooms/) 里的邀请链接。只填一样的用户名拿不到房主身份。

## 第二步：手动完成 Agent 接入向导

在右侧「成员」面板底部点击「接入 Agent」：

![成员面板的真实入口：邀请成员与接入 Agent 并排显示。隔离演示界面截图，裁切后只保留按钮。](/media/interface/member-actions.png)

隔离演示界面截图（裁切），展示当前入口位置，不是新一轮真实模型接入验收。

![「把 Agent 接入 Hive」弹窗的第一步：列出 Codex、Claude Code、GitHub Copilot、OpenCode、omp、Gemini CLI、Antigravity 和 OpenClaw，并显示本机检测到的版本。](/media/screens/onboard.png)

演示环境界面截图：人名、房间和仓库都是示例数据，会跟随文档的明暗主题切换。每张卡片下方是这台电脑检测到的 CLI 版本。

1. 选择已经安装并登录的 Runtime，例如 Codex 或 Claude Code，手动点「下一步」。选择卡片不会自动跳转。
2. 选择「只读」权限，再手动点「下一步」。默认是工作区档，这次练习请改成只读。
3. 核对 Agent 名称，例如 `guide-agent`；在本机启动时把数量保持为 `1`。本机批量接入支持 `1–5` 个同类 Agent，但第一次不用开满。
4. 点击「在本机启动」。如果想让 Agent 跑在另一台电脑上，改用「复制命令」，到那台电脑的终端里运行。
5. 确认成员列表中出现这个 Agent，并查看接入结果是否上线。仅复制命令还不等于 Agent 已经连接。

复制的接入命令包含认证信息，不要贴进公共聊天室或截图。命令在哪台电脑上运行，Agent 就用哪台电脑的 CLI 和文件。

## 第三步：发一条范围明确的消息

在消息框输入 `@`，从候选列表选中刚接入的 Agent，发送：

```text
@guide-agent 请只回复“已连接”，不要读取文件或调用工具。
```

`guide-agent` 是示例名，实际使用接入时确认的名称。消息里的限制说明任务范围，权限档则限制可执行操作；两者不是同一件事。

查看消息对应的任务状态，等待 Agent 回复。Agent 开始处理后，消息下方显示「进行中」，回复卡片里能看到它正在做的步骤：

![Agent 正在执行的任务卡片：标题行显示「执行中」和当前命令，下方是它的说明、引用的原消息，以及思考、运行命令、编辑、读取等步骤汇总。](/media/screens/running.png)

演示环境界面截图：人名、房间和仓库都是示例数据，会跟随文档的明暗主题切换。

点击「Agent 任务」或消息上的任务状态可进一步看详情、执行过程和可用的操作。这个最小任务只验证接入与回复，不证明它已经能修改代码、访问所有 MCP 或调用任意模型。

## 第四步：按需要设置主 Agent

房间里第一个加入的 Agent 会自动成为主 Agent（房间里出现一行提示，底部状态栏标「自动」），不写 `@` 也有人接话。想换人，点底部状态栏的主 Agent 切换，或在「管理房间」选择「主 Agent」、从成员菜单把一个 Agent 设为本房间的主 Agent；手动设的不会被自动换掉。

- 普通人类消息没有明确接收者时，由主 Agent 接话；它可以自己完成，也可以再委派。
- 明确 `@` 当前房间里的成员时，主 Agent 不会再额外接管。
- 在设有主 Agent 的房间，不带 `@` 地回复一个 Agent 的消息时，优先交给被回复的 Agent。
- 自动设的主 Agent 被删除或移出时会换成下一个在线的 Agent；手动设的被移除、或房主取消了主 Agent 时，普通无提及消息不保证有人处理。访客还受到邀请权限和房主审批的约束。

完整规则、邀请和房间工作区见 [房间与成员](/guides/rooms/)。

## 遇到问题先检查什么

| 看到什么                   | 先做什么                                                     |
| -------------------------- | ------------------------------------------------------------ |
| 客户端打不开，停在出错画面 | 看画面上写的原因，点「重试」；还不行点「打开日志目录」看日志 |
| 接入失败                   | 检查对应 CLI 是否已经登录，查看本机 Agent 的状态和日志       |
| 消息没有回复               | 检查 Agent 名称、在线状态，任务是否在排队或等房主批准        |
| 任务失败或结果未知         | 先看任务详情和已有产物，不要马上重跑可能有副作用的任务       |

用 CLI 启动时浏览器打不开界面，先确认终端里的 `hive` 还在运行，用终端显示的实际地址打开。

停止、重试、引导和严格条件下的自动恢复见 [任务指南](/guides/tasks/)；更多问题看 [排障指南](/reference/troubleshooting/)。

## 注意事项与下一步

- 只读是推荐的首次试用档位，不等于消息或模型服务不会接收到你主动发送的内容。不要发送密钥和私人数据。
- 「完全访问」没有沙箱，不是接入成功的必要条件。处理真实项目之前先读 [权限指南](/guides/permissions/)。
- 截图里的名称、任务都是演示数据。
- 接下来可看 [消息与附件](/guides/messaging/)、[飞书与微信](/guides/im/)、[用量与费用](/guides/usage/) 和 [多 Agent 协作](/guides/collaboration/)。
