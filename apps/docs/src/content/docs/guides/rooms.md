## 有什么用

一个房间是一组人、Agent、消息和协作事项的共同空间。按项目或用途分房间，可以减少上下文混杂，并明确哪些访客能看到哪些内容。

房间工作区告诉本机 Agent 应该在哪个目录工作，但房间本身不是文件系统沙箱。多个房间指向同一目录时仍可能改到同一份文件；隔离开发任务要结合 [权限](/guides/permissions/) 和 [工作区任务线](/guides/worktrees/)。

## 创建并整理房间

1. 用房主身份在左侧创建房间；普通访客没有创建和管理房间的权限。
2. 打开「管理房间」，核对名称，并在需要文件操作时选择实际存在的工作目录。
3. 核对「主 Agent」：默认是「自动」，第一个加入房间的 Agent 自动成为主 Agent；也可以手动选一个当前房间的 Agent，或选「不设置」。右侧成员列表会标出「主」，输入框也会说明无提及消息交给谁。
4. 按需要重命名或归档房间。房间顺序可以拖动调整，触屏用拖动把手；键盘用 `Alt + ↑/↓`。排序保存在当前浏览器，不是所有人的统一排序。

未读标记跟着人走：已读位置存在 Server 上，你在浏览器里看过的房间，换到桌面客户端或手机上打开也是已读，开着的其他设备会马上跟着消失。房主不管从哪台设备进来都算同一个人；访客各记各的。页面在后台时来的消息不算读过，回到页面时才记。「提及我」的未读和定时任务面板的醒目提示也一样。

Git 工作区会在房间标题附近显示分支，分离 HEAD 时显示短提交号。它是目录当前状态的提示，不是某个 Agent 的修改已通过 review 或已经合入的证明。

## 让主 Agent 接话

主 Agent 是普通无明确接收者消息的默认处理者，不是强制监听所有消息的管理员。

### 默认主 Agent

- **自动设定**：房间没有主 Agent 时，第一个加入（上线）的 Agent 自动成为主 Agent；同时进来好几个时，优先这台电脑上的本机 Agent，其次按上线先后。新建房间时在向导里选好的 Agent 也按这条规则。
- **房主手动的永远优先**：房主手动指定的主 Agent 不会被自动逻辑换掉；房主手动「取消主 Agent」或在「管理房间」选「不设置」后，这个房间不再自动设。想恢复，在「管理房间」里选回「自动」。
- **自动顺延**：自动设的主 Agent 被删除、移出房间（访客被移除或到期也算）时，换成房间里下一个在线的 Agent（同样本机优先）。只是离线、重启不换。房主手动设的被删除时保持原样，底部状态栏变成「设主 Agent」，并给出建议人选。
- **房间提示**：自动设定或自动顺延时，房间里会出现一行系统提示，说明谁成了主 Agent、怎么改；它不 @ 也不唤醒任何人。底部状态栏和「管理房间」里，自动设的主 Agent 标「自动」；要换人，点底部状态栏的主 Agent →「切换主 Agent」。

| 消息情形                                            | 路由规则                                                     |
| --------------------------------------------------- | ------------------------------------------------------------ |
| 房间设有主 Agent，人发普通消息且没有 `@`            | 交给主 Agent                                                 |
| 房间设有主 Agent，不带 `@` 回复某个仍在房间的 Agent | 优先交给被回复的 Agent                                       |
| 明确提及在场成员，包括人或 `@all`                   | 主 Agent 不额外接管；`@all` 不等于广播调用所有 Agent         |
| 提及的名字不在房间，或 Agent 已离线超过两分钟       | 没有其他有效接收者时，可交给主 Agent；短暂断线仍按原目标排队 |
| 访客未获准直接调度房主的 Agent                      | 无提及消息不会隐式交给主 Agent；明确调度仍可能等待房主批准   |

回答提问、Agent 回执、进度和定时触发有各自的规则，不套用普通消息的主 Agent 路由。让 Agent 拆分任务和汇总结果，见 [协作指南](/guides/collaboration/)。

## 邀请普通成员

1. 在「成员」面板底部点「邀请成员」。
2. 选择有效期：1 小时、12 小时、24 小时、永久或自定义；界面默认 24 小时。
3. 核对两个独立开关：允许直接让房间里的 Agent 干活，以及是否展示 Agent 执行过程。默认需要房主批准调度，执行过程默认可见。
4. 生成邀请链接，私下发给需要加入的人。链接有效期内可被多人使用，不是一次性邀请。
5. 在成员列表查看访客剩余时间；需要时对单人续期、移除，或在邀请弹窗对整个链接续期、撤销。

撤销整个链接会影响凭它进入的所有人。永久邀请也可以撤销，不代表永远不受管理。

![身份边界示意：本机房主可管理 Server，房主设备登录默认可查看，限时访客仅访问被邀请房间](/media/codex2/room-access.svg)

这是原创身份流程示意，不是实际界面截图；「登录为房主」和「获批管理 Server 所在电脑」是两种不同授权。

### 访客能做什么

- 只访问被邀请的房间，不能新建或管理房间、开新话题、追加 Agent 对话轮数。
- 默认调度房主的 Agent 需要批准；允许直接调度的邀请会扩大使用能力，应谨慎发放。
- 可以使用「带入我的 Agent」生成命令，在自己的电脑运行。带入的 Agent 只进入同一房间，并随访客到期或被移除。
- 能否看到详细执行过程由邀请设置决定；隐藏过程不等于模型请求不包含任务内容，也不等于文件权限沙箱。

## 房主换设备登录

在 Server 所在电脑点左下角头像，打开用户菜单里的「在其他设备登录」，点「显示登录二维码」。手机或另一台电脑扫码，或打开链接，在能访问 Server 的同一网络中登录。

- 配对票 5 分钟内有效，只能用一次；别把二维码作为公开附件。
- 每台设备取得独立会话，而不是共享接入令牌。设备会话最长 30 天，闲置 7 天失效。
- 飞书私聊的「在网页查看」或 `/web` 可以带 24 小时有效的一次性登录票；换设备时重新获取，不要转发。群卡片不带房主登录票，群里的 `/web` 不提供私聊登录入口。
- 在同一个弹窗里可以退出已登录设备。经 IM 登录的设备被退出时，该连接此前发出的登录票也会作废。

远程房主设备可以查看本机目录、Agent 状态、日志和 MCP 列表等；启动或停止本机 Agent、清空房间、修改 MCP 等管理操作需要申请授权。终端执行和写文件还可能需要单次批准，不能把「已登录」当成所有操作都已获准。细节见 [权限指南](/guides/permissions/)。

## 新话题、归档和清空不是同一件事

| 操作     | 适合什么情况                   | 要注意什么                                         |
| -------- | ------------------------------ | -------------------------------------------------- |
| 新话题   | 旧上下文开始干扰当前任务       | 下轮换新会话，旧消息折叠保留、可搜索；不是删除历史 |
| 归档房间 | 暂时不用这个协作空间           | 是整理操作，不等于任务已经完成或文件已合入         |
| 清空房间 | 确实要删除该房间消息和调用记录 | 不可恢复；默认同时归档白板，不是永久删除白板历史   |

清空房间仅房主及获批管理设备可用。白板若仍有事项占用已登记工作区，整次清空会被拒绝，不会靠清聊天解除占用；不要绕过保护。白板归档与恢复见 [协作指南](/guides/collaboration/)。

## 注意事项

- 用户名只是显示名。不要把改成同名、复制共享令牌或转发房主登录票当成普通邀请方式。
- 成员可看到的消息与 Agent 可访问的本机文件是不同边界；面向外部成员的任务应先限制目录与权限。
- 房间标题、主 Agent、分支标签和权限按钮按当前实现描述；图中没有任何真实成员、工作目录或登录票。
- 更多安全要求见 [安全参考](/reference/security/)，发送方式见 [消息与附件](/guides/messaging/)。
