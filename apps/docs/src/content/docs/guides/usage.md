## 有什么用

团队共用云端 Hive 时，Agent 可分布在不同电脑，模型账号和费用不会自动合并。部署与接入步骤见[云端部署与多人共用](/guides/cloud-deployment/)。

用量统计帮助你理解「哪一个 Agent、哪一轮、为什么消耗变大」。它记录 Runtime 返回的 token 数据，再结合模型价格估算费用，不是模型服务的正式账单，也不是自动扣费账户。

要控制开销，先限制任务范围和并行数量，再观察真实用量。Hive 的对话预算是 Agent 互相唤醒的刹车，不是美元额度硬上限。

## 第一步：找到每轮与房间统计

1. 打开「Agent 任务」，选择一轮任务看详情和用量。
2. 查看输入、输出、缓存命中率、会话大小，以及是否有大额缓存写入提醒。
3. 在任务面板底部找到「用量 · 当前房间」，选择 24 小时、7 天或 30 天。
4. 按 Agent、日期和最近的大额缓存写入核对消耗，而不是只看总金额。

失败、被停止和结果未知的轮次，只要已取得 Runtime 用量也照常记录。停止任务不会抹掉已经发生的模型消耗；正在运行的当前轮也可能还没有完整记录。

## 第二步：看懂 token 的四个桶

| 指标       | 含义                               | 不代表什么                 |
| ---------- | ---------------------------------- | -------------------------- |
| 未缓存输入 | 没有归入缓存读取或写入的输入 token | 不是你手打文字的字数       |
| 缓存写入   | Runtime 报告的新建或重写缓存 token | 不保证下轮一定能命中       |
| 缓存读取   | Runtime 报告的已命中缓存输入 token | 不一定免费，取决于服务计费 |
| 输出       | 模型返回的输出 token               | 不等于网页上可见字符数     |

输入总量按三个输入桶汇总。不同 Runtime 原始字段不同，Bridge 会做归一化；不要把供应商原始「总输入」再与缓存字段相加而重复计算。

缓存命中率是缓存读取占输入总量的比例。会话大小展示观测到的上下文峰值，若 Runtime 提供上下文窗口，也会显示它；不要把它当成本机磁盘大小。

## 第三步：配置价格并核对估算

在统计区展开「价格与提醒设置」，为记录到的模型配置四项单价：未缓存输入、缓存写入、缓存读取和输出，单位是「每百万 token，美元」。

```text
估算美元费用 =
  (未缓存输入 × 输入单价
   + 缓存写入 × 写入单价
   + 缓存读取 × 读取单价
   + 输出 × 输出单价) / 1,000,000
```

例如使用纯教学虚构价格，未缓存输入 1,000 token、单价 2 美元/百万，输出 500 token、单价 8 美元/百万，其余为零，估算为 0.006 美元。这不是任何实际模型的报价。

- 配置了该模型价格时，优先按本浏览器配置计算。
- 没有价格时，尝试使用 Runtime 自报费用；Claude Code 的自报费用也是估算，Codex 不提供费用。
- 两者都没有时金额未知，不是零费用。汇总会提示部分模型没有计入，不能把不完整总数当作全部成本。
- 价格和提醒参数只保存在当前浏览器，换设备不会自动同步；统计用量本身由 Server 保存。

## 缓存为什么突然重写

任务详情区分已观测的事实和「可能原因」，例如新会话、恢复会话、请求间隔、缓存写入类型。没有直接观测到有效期时，才使用设置中的「假定缓存有效期」来辅助解释。

1. 先看是否是新会话或已恢复会话。
2. 看间隔来自模型请求时间还是按上一轮结束估算。
3. 看是否确实观测到缓存写入类型，不要把推测原因当成供应商确认。
4. 会话明显膨胀时，先把必要结论整理出来，再由有权限的人在房间顶部开「新话题」。下一轮 Agent 换新会话，旧消息仍保留。

新话题不是「保证更便宜」按钮：它也可能丢失已有缓存，需要重发必要上下文。修改假定有效期、大额写入阈值、会话大小阈值，只改变解释或提醒，不改变供应商缓存规则，也不会硬性阻止模型请求。

## 对话预算：防止 Agent 连续互相唤醒

当人长期不参与时，Agent 之间的自动转交有多维限制：连续轮数、转交深度、单链消息数、每分钟回复数，以及同一对 Agent 的每日唤醒数。达到相应限制时会出现被阻止或需要继续的状态。

- 房间当前默认最多 50 轮连续 Agent 转交；进度消息和服务端子任务回执不计入这项轮数。
- 人类主动发言会重置连续轮数预算；到点的定时消息不当作人重新在场。
- 有权限的人可按界面提示「追加轮数」并恢复被预算拦下的调用。先核对原任务是否仍该继续，不要为了绕过限制让 Agent 换名字、另起转交链或反复发送。
- 访客不能追加轮数；轮数额度不会转换成美元额度，也不能保证每一轮成本相同。

预算限制与任务状态的关系见 [任务指南](/guides/tasks/)，委派与进度约定见 [协作指南](/guides/collaboration/)。

## 注意事项

- 当前用量采集来自已接入的 Runtime 字段，不保证每种 Runtime、旧版本 Agent 或每个模型都提供记录。「没有用量记录」不是免费。
- 模型网关、订阅、折扣、缓存计费和币种转换可能与页面估算不同，最终以模型服务账单为准。
- 停止、失败、重试和自动恢复可能已经消耗 token；重复运行前先检查已有结果和副作用。
- 本页不配置真实单价、不调用收费模型，也不承诺节省比例。开始任务前合理选择 [Agent 数量](/guides/agents/) 和 [权限](/guides/permissions/)，比事后只看总金额更可靠。
