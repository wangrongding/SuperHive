## 记录以后要做的事

右侧「进展」把需要你处理、待办、进行中、已就绪和里程碑放在一起；标签数字是未完成待办与需要你处理的总数，悬停可看各自条数。每个房间有独立待办分区，输入标题即可添加；每条显示创建人，可以编辑备注、指派负责人、勾选完成、重新打开或删除，用上下箭头调整顺序，顺序会保存。已完成事项默认折叠。

- 消息操作里的「记为待办」取正文摘要作标题，并保存来源；待办里的来源链接可以跳回原消息。记录不会派活。
- 未完成事项点「交给 Agent」，选成员后确认「发送任务」，会以你的名义发送一条 @ 消息并设置负责人。离线 Agent 上线后接活；这不等于任务已完成，不会自动勾选。
- 编辑时改选 Agent 为负责人，按钮会显示「保存并派给 Agent」；确认保存也会派活。只修改标题或备注，不会重复派给原负责人。
- Agent 可用 `hive_todo_list` 查看、`hive_todo_add` 添加、`hive_todo_update` 更新或设置 `completed: true`。标题最多 200 字符，备注最多 5000 字符；每个房间最多 1000 条。
- 房主及使用房间成员凭证的人可以修改；访客（包括访客 Agent）默认只读，访客允许提及 Agent 的权限不授予待办编辑权。创建人由成员身份记录，不由客户端任意填写。
- 待办保存到 SQLite，刷新、重连、重启或开启新话题不会丢失。来源消息被撤回或清空后无法跳回，但已经明确保存的待办摘要仍保留；需要时单独删除待办。

待办记「以后要做、还没开始」；正在做、已经交付或被阻塞的事项继续登记在「进展」白板。到点提醒使用[定时任务](/guides/collaboration/)，不要把待办当作自动执行队列。

## 任务状态和 Agent 在线状态不同

成员在线只说明连接存在，不代表一项任务已经开始或成功。每次提及派出的调用会在消息下方显示状态；点「详情」查看收到时间、队列、最近事件和原因。

| 页面状态       | 表示什么                                       | 你可以做什么                               |
| -------------- | ---------------------------------------------- | ------------------------------------------ |
| 排队中         | 已登记，尚未开始；可能离线或排在别的任务后面   | 看队列和派出时间，不重复发同一任务         |
| 已送达         | Agent 已确认收到，但不等于完成                 | 等待执行，必要时打开详情                   |
| 运行中         | Agent 正在处理，可能包含工具执行或自动等待重试 | 看执行过程，有新要求可引导或停止           |
| 等人回答       | 有待回答的问题                                 | 回复原问题，不必另提及 Agent               |
| 等你决定       | 中断或上游出错后不能安全地自动接着做           | 读卡片上的原因，再点「继续」或「忽略」     |
| 已完成         | Agent 正常结束并报告结果，可能标注无需回复     | 核对交付和验证，不把它当成已发布或已合入   |
| 失败           | 执行有明确错误                                 | 看原因，修好前置条件再重试或继续           |
| 被拦截         | 权限、访客授权或协作预算等限制阻止了调用       | 读拦截原因；只有对应的人或授权流程能放行   |
| 停止中／已停止 | 已请求停止／确认本次调用停下                   | 核对已经产生的影响，再决定是否重试         |
| 结果未知       | 中断、长期无进度或停止未确认，无法确认结局     | 先检查实际文件、提交或外部结果，不直接重跑 |

![运行中的任务：消息下方的状态条显示「@codex 进行中」和已用时间，带「详情」「停止」；Agent 的回复卡片显示「执行中」、当前命令和步骤汇总。](/media/screens/running.png)

演示环境界面截图：人名、房间和仓库都是示例数据，会跟随文档的明暗主题切换。

“已送达”是接收进度，不是额外的成功证明；详情比一个颜色标签包含更多依据。子任务回执状态也不等于主任务已经验收。

## 运行中怎样查看和补充要求

Claude Code、Codex、OpenCode、omp、Gemini CLI、agy 支持实时执行过程，展示工具、命令、文件和进度等观测。执行过程仅保存在 Server 内存，不落库、不发 IM；结束后可暂时查看，但刷新或重启后不要把它当成持久审计记录。

Agent 忙时，新消息默认排队。支持的运行时可在工具调用间隙接收「引导」：

1. 对排队中的人类消息点「引导」，或用输入框旁的「引导」发送补充要求。
2. 说明这是补充范围还是要改变方向；引导不会撤销已经完成的命令或写入。
3. 若要另起任务，使用「停下当前，改做这条」，先停当前调用再处理新消息。

Claude Code、Codex、OpenCode、omp 支持引导；仅对人直接发的消息有效。绑定到另一条 worktree 任务线的消息会保留排队，不能通过引导把两个 cwd 混在一起。见[任务线绑定](/guides/worktrees/)。

本机设置中的「人发的消息自动引导」默认关闭。开启后要更注意写清范围，避免普通排队补充意外改变正在执行的目标。

## 停止不会回滚已经做过的事

点任务的停止按钮是在终止 **这一项调用**，不是撤销文件、提交、网络请求或外部消息。

| 运行时                   | 停止方式与结果                                                            |
| ------------------------ | ------------------------------------------------------------------------- |
| Codex、OpenCode、omp     | 中断当前回合，Bridge 进程可保持在线；确认后显示已停止                     |
| Gemini CLI、agy          | 同上，经 ACP 中断当前回合                                                 |
| Claude Code              | 先请求运行时中断当前回合和工具；约 5 秒内未确认才结束进程，结果按未知处理 |
| GitHub Copilot、OpenClaw | 结束对应子进程，是否完成某个外部操作仍需核对                              |

Agent 把几条消息合在一轮里做时，停止针对的是**这一轮**：在其中任意一条下面点「停止这一轮」，同一轮的几条一起停下。访客只能停自己发起的；同一轮里还有别人发起的消息时，按钮点不了，悬停会说明原因，需要房主来停。

服务端长时间没有收到停止确认时也会把调用转为结果未知，不会永远显示停止中。迟到的结果可能随后更新记录；在此之前不要假定没有副作用。

### 撤回消息的范围

撤回未结束的任务消息，确认框默认「撤回并停止」：排队或被拦截的直接取消，执行或等人回答的按停止处理。也可选「只撤回」，让当前工作继续但不再回复该消息。

这只停止该消息直接派出的调用，**不会连带停止它用 `hive_invoke` 委派的所有子任务**。若多条消息被合在一轮执行，其他消息仍会继续处理：这条会显示回执行中并写明「这一轮会继续」，这一轮结束后标为已停止。需要停止子任务时查看对应调用，明确逐项处理。

## 重试、继续、重启、重置分别做什么

| 动作                 | 作用                                    | 不能据此推断                 |
| -------------------- | --------------------------------------- | ---------------------------- |
| 重试任务             | 再次处理失败或已停止的调用              | 前一次的写入已撤销           |
| 上游错误后的「继续」 | 接着原会话处理未完成内容                | 一定无重复操作，或模型已恢复 |
| 重启本机 Agent       | 重新启动该 Agent 的进程，读取保存的状态 | 每项中断任务都重新执行       |
| 重置会话／新话题     | 不再沿用相应旧会话上下文                | 文件、提交、外部状态已被重置 |

结果未知时先打开详情，再检查实际工作区、提交记录和外部系统。已做的部分写清楚，给出继续的范围；重复部署、付款、删除或发送消息尤其不能靠“重试一次看看”。

被协作预算拦截的调用可按页面提示由人「继续 10 轮」；这不是授予文件权限。访客授权和工具审批也各有自己的流程，见[权限与审批](/guides/permissions/)。

## 中断后的安全自动恢复：必须全部满足

Bridge 启动时若发现上次留有未结束的执行记录，会检查能否安全重跑。**不是所有崩溃、断电、关机或强制结束都会重跑**。

![安全自动恢复示意图：检查本轮副作用记录、旧运行时退出、两次额度和原任务有效性，全部满足才按原消息重新执行，否则不自动重跑。非实际界面截图。](/media/codex4/safe-recovery.svg)

图为原创流程示意图，不是实际调用详情截图。

只有以下条件全部满足，才会在重新连上 Server 后按原消息自动重新执行，最多 **2 次**：

1. **有可核对的中断执行记录，且未记录可能产生副作用的步骤**。读取、搜索、思考及明确的只读 Hive 工具可被视为只读；不认识的命令或工具按可能有副作用处理。
2. **旧运行时子进程已经退出**。Bridge 会短暂等待，仍有旧进程在跑时不另起一份。
3. **这条原消息的自动恢复次数还没用完**。达到两次上限后不再自动重跑。
4. **能取回原消息，原调用仍允许恢复**。消息未撤回、调用未被人停止或收起，且没有已经落定的结果；不能用自动恢复把人已处理的任务重新冲回运行中。

自动恢复会在状态说明、执行过程和结束说明里标出「自动恢复第 N/2 次」。它是 **按原请求重新执行**，不是保证从某个文件写入的断点继续。

写文件、发消息、更新白板、创建任务线、委派和外部工具调用等可能有副作用。进度消息虽然不算最终回复，仍不应在崩溃恢复中被重复发送。创建 worktree 后的正常[准备交接](/guides/worktrees/)是另一种机制，不等于可以重放这些操作。

不满足条件时通常保留或报告结果未知，交给人核对；人已经停止、撤回或处理的调用不再自动排队。无副作用判断依赖 Bridge 的工具观测和保存记录，**不是对任意插件、外部系统或隐藏操作的绝对保证**。

## 模型服务错误后的自动继续是另一件事

Claude Code、Codex 遇到上游限流、过载、5xx 或断流时，如果这一轮尚未做可能有副作用的操作，可等 **1 分钟、3 分钟**后接着原会话自动继续。

已做过改动、等待次数用完，或模型本身不存在／不可用时，报告失败并说明原因。可恢复的上游错误按钮显示「继续」；先检查模型、账号与错误说明，再决定是否继续或换模型。

自动接着做不安全，或等待次数用完时，消息下方会出现「等你决定」，并计入左侧「需要你处理」：

![「等你决定」状态条：@omp 等你决定，原因是上游模型服务出错 503，右侧有「详情」「继续」「换个模型重试」「忽略」。](/media/screens/decide.png)

演示环境界面截图：人名、房间和仓库都是示例数据，会跟随文档的明暗主题切换。这张卡片不会过期。点「继续」会接着中断的那一轮会话，先核对已经做过的再往下做；旧进程还在跑、停止还没确认或 Agent 离线时不能点继续，避免同一任务同时跑两份。

这与崩溃后的原消息重跑不同，不要把两个机制当成“任何失败都自动重试两次”。

## Server 重启与睡醒保护

网页启动的本机 Agent 会记住配置和“应该运行”的标记。Server 重启时恢复未被手动停止的 Agent；可交接的存活进程会被接管，需要重新拉起的多个 Agent 会错开约 2 秒启动。手动停止过的不会自动复活；10 分钟内反复意外退出 5 次会停止自动重启，修好后需手动启动。

电脑重启后要先启动 Server，或已配置登录自启，Agent 才会回来。这是恢复进程，不是对每一条中断任务重新授权。操作说明见 [CLI 参考](/reference/cli/)。

睡眠或合盖时 Server 和 Agent 可能都暂停。醒来后：

- 心跳扫描检测时间跳变，先给连接一轮宽限，不立即因旧心跳断开全部成员。
- 任务扫描对运行中调用给约 **2 分钟**恢复宽限，让 Agent 重连并报告状态；真卡住的任务之后仍按规则判为结果未知。
- 这不保证网络、模型服务或所有 CLI 恢复成功，也不保证错过的定时任务补跑。

「熄屏后保持在线」可在支持的平台上减少空闲睡眠，屏幕仍可熄灭；当前内置支持 macOS、Windows。合盖、手动睡眠、强制睡眠及电池策略等仍有限制，不能当作持续在线承诺。需要长期服务请看[部署参考](/reference/deployment/)。
