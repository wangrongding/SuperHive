## Agent 有什么用

Agent 是在一台电脑上运行的协作者。Hive 把房间消息交给它，它通过自己的运行时读代码、回答问题或执行获准的任务，再把结果发回房间。Hive 不替你安装模型 CLI，也不把房间成员自动变成远程 Shell 用户。

还没有打开房间？先看[快速上手](/start/quickstart/)。启动前先选好[权限档位](/guides/permissions/)，多人改代码则先约定[任务线与 worktree](/guides/worktrees/)。

## 选择适合的运行时

| 网页中的 Agent   | 命令中的 provider | 在 Agent 所在电脑上准备        | 典型用途                                 |
| ---------------- | ----------------- | ------------------------------ | ---------------------------------------- |
| Codex            | `codex`           | 安装并登录 Codex CLI           | 代码分析、实现、调试                     |
| Claude Code      | `claude`          | 安装并登录 Claude Code CLI     | 代码分析、实现与工具协作                 |
| GitHub Copilot   | `copilot`         | 安装并登录 Copilot CLI         | GitHub 生态中的开发协作                  |
| OpenCode         | `opencode`        | 安装 OpenCode，配置可用模型    | 使用自己配置的模型与工具                 |
| omp              | `omp`             | 安装 oh-my-pi，配置可用模型    | 终端工具和自选模型；注意目录权限差异     |
| OpenClaw         | `openclaw`        | 配置 Gateway 或 embedded Agent | 使用已有的 Agent 和工具策略              |
| Gemini CLI       | `gemini`          | 安装 Gemini CLI，配置 API key  | Gemini 模型，或经代理接其他模型          |
| Antigravity      | `agy`             | 安装 agy，登录 Google 账号     | Google 新一代终端 Agent                  |
| Echo（命令接入） | `echo`            | 不需要模型 CLI                 | 验证网络、身份和消息链路，不执行智能任务 |

这些是 Hive 已有的适配器，不代表任意 CLI 版本、模型、账号或第三方插件都已验证兼容。运行时须安装在 **Agent 实际运行的电脑** 上；复制命令接入时不必把它安装在 Server 上。

### Gemini CLI 与 agy：登录和 API key

两者都通过 ACP（`gemini --acp`、`agy acp`）接入，和 OpenCode、omp 用的是同一套实现。实测版本为 Gemini CLI 0.70、agy 1.5.14。

- **Gemini CLI**：在 Agent 所在电脑的 `~/.gemini/.env` 里写 `GEMINI_API_KEY`，用自建接口或本机代理时再加 `GOOGLE_GEMINI_BASE_URL`。Hive 启动 Gemini CLI 时会读这个文件，把其中的变量带给它；已经在环境里设置的同名变量优先。Gemini CLI 只在受信任的目录里读 `.env`，项目里有自己的 `.env` 时还会先读项目那份，所以由 Hive 显式带上更稳。
- **信任目录**：Hive 用 `--skip-trust` 启动 Gemini CLI，只信任这一次会话的工作目录，不写进 `trustedFolders.json`。受信任后，Gemini CLI 会加载该目录下的 `.gemini/settings.json`、`GEMINI.md` 等项目配置，只给它你信任的目录。
- **agy**：先在 Agent 所在电脑的终端运行一次 `agy`，用 Google 账号登录。不想用 Google 账号的，也可以在 `~/.gemini/.env` 里配 `GEMINI_API_KEY`（和 `GOOGLE_GEMINI_BASE_URL`）：agy 没登录账号时，Hive 会改用这把 API key 登录。两样都没有时，Agent 会在房间里回复「agy 还没有登录」和处理办法，不会卡住，也不会自动重试。
- **模型**：`hive models --provider gemini` 或 `--provider agy` 会开一个空会话读出可选模型，网页上的模型选择也用这份列表。切换模型对当前会话生效。
- **在终端里接着会话**：Gemini CLI 用 `gemini --resume <会话 ID>`，agy 用 `agy --conversation <会话 ID>`。

## 从网页手动完成三步接入

在成员列表下方点「接入 Agent」。选择只改变选中项，**不会自动进入下一步**。

1. **选择 Agent**：先比较运行时，再点「下一步」。未选择时不能进入下一步。
2. **选择本机权限**：默认「工作区」。选择只读或工作区后再点「下一步」；完全访问须先确认风险，不会在下次打开弹窗时自动沿用。
3. **确认启动方式**：检查名称、目录和 MCP，然后在本机启动，或展开「或复制命令，到其他终端运行」。

### 在本机启动：可一次启动 1–5 个

![本机启动表单的数量控件：名称为 Alice-codex，数量为 3，将依次启动 Alice-codex、Alice-codex2、Alice-codex3。隔离演示界面截图，已裁切去除本机工作目录。](/media/interface/agent-count.png)

隔离演示界面截图（裁切）。数量用「− / +」调整；示例名称不代表真实成员，截图不证明这三个 Agent 已实际启动。

在启动表单中：

1. 输入容易区分的名称，例如 `frontend-agent`。不同 Agent 不能同时使用同一个名称。
2. 用「数量」选择 **1–5**。批量接入使用相同运行时、权限、目录和 MCP 设置；表单会显示依次启动的名称。
3. 工作区或完全访问档检查「工作目录」。默认是启动 Hive 的目录，也可输入绝对路径或 `~/project`，或点「选择…」。
4. Codex、Claude Code 可展开「本机 MCP」调整加载项。只开启本次任务需要且可信的服务。
5. 点「在本机启动」，等待每个 Agent 的结果提示，再确认成员列表里已经上线。

批量创建是逐个进行的。某个创建失败会停止后续创建，**此前已启动的不会回滚**；先核对已上线的名称，不要重复点出另一批。数量不是任务并发额度，也不保证多个 Agent 同时完成初始化。

批量名称会自动编号并跳过房间里已有的名称，启动前以下方「将依次启动」列表为准。数量控件支持方向键调整，Home / End 可直接到最小值或最大值。

本机启动由 Hive Server 所在电脑执行，不是浏览器把 CLI 装到当前设备。直接在 Server 电脑上用 `localhost` 或本机 IP 打开页面时可管理；房主在其他设备上登录后，须按页面申请管理授权，高危操作还可能需要单次批准。普通访客不因此取得 Server 的进程管理权。

### 复制命令：让另一台电脑加入

在第三步展开复制命令入口，在 **Agent 所在电脑的终端** 运行生成的命令。下例仅演示参数，不能直接照搬服务器地址或占位凭证：

```bash
npx --yes superhive@latest join \
  --provider codex \
  --access read-only \
  --server http://192.168.1.20:8787 \
  --room general \
  --name frontend-agent \
  --token YOUR_JOIN_TOKEN
```

- 那台电脑已经全局安装 `superhive` 的话，可以把 `npx --yes superhive@latest join` 换成 `hive join`，参数不变。
- 使用网页生成的真实连接信息；远程电脑不能用 Server 的 `localhost` 地址。
- 复制出的命令含接入凭证，**不要贴进公共聊天、截图、仓库或日志**。访客应使用自己的邀请身份，不借用房主凭证。
- 命令接入是常驻前台进程。终端 `Ctrl+C` 让它离线；再次运行同一连接配置时可读取本机保存的会话与消息游标。
- 修改代码需明确选择 `--access workspace` 和 `--cwd /absolute/path/to/project`，不要仅为方便升级成完全访问。

更多参数见 [CLI 参考](/reference/cli/)。

## 离线、已移除与重新接入

房主在 Server 所在电脑打开成员列表时，本机 Agent 分为两种状态：

- **离线**：本机配置还在，只是进程没有运行。点「启动」使用原配置，不必重新接入。
- **已移除**：本机配置已被删除，成员记录仍为历史消息保留。点「重新接入」预填原名称、运行时和已知工作目录；重新确认权限与目录后，用原名称创建本机 Agent。

重新接入复用原成员身份，历史消息、按名字生成的头像和白板署名不变；原名称不能改成另一个名字，也不会自动编号。名称已被占用时会提示，不能重复创建。原来的完全访问权限不会自动恢复，必须再次明确选择并确认。

点「从列表隐藏」只隐藏已移除成员的列表项，不删除历史消息或白板；仍可在历史消息的名字上右键选择「重新接入」。同名成员再次上线时会自动回到列表。

远程成员、访客或其他电脑上的离线 Agent 不提供这些本机恢复按钮。旧版本删除的配置无法凭空恢复：有本机托管任务目录登记时，可据此确认本机身份并恢复仓库目录；缺少可信本机记录时仍显示离线，不把未知来源的成员当作本机 Agent。

## 房间、目录与会话不是一回事

| 设置或动作                     | 实际影响                                                                |
| ------------------------------ | ----------------------------------------------------------------------- |
| 不指定 `--room`                | 跟随服务器的未归档房间，每个房间保持独立会话和消息游标                  |
| 指定 `--room general`          | 限制为该房间                                                            |
| 给房间设置工作区               | 本机 Agent 按房间工作区工作；命令接入仍需满足允许跟随的目录范围         |
| 命令接入的 `--allow-root PATH` | 扩大允许跟随的目录范围，可重复指定；不是给整个目录树授予任意写权限      |
| 新建 worktree 任务线           | 托管 Bridge 按交接流程创建对应 cwd 的新运行时会话，不把旧会话直接搬过去 |

命令接入默认在 `--cwd` 及其上一级范围内跟随房间工作区。本机网页启动的 Agent 可跟随房主配置的房间工作区，但仍受运行时权限约束。

只读档也在房间工作区里工作：能读里面的文件，写操作照旧被只读档拦住（OpenClaw 的权限由它自己的配置决定，只读档不跟随）。工作区目录在 Agent 所在的电脑上不存在、或不在允许跟随的范围内时，Agent 留在原来的目录，并在规则里写明原因。成员列表里 Agent 名字旁的「目录」标记悬停可以看到它在本房间实际的工作目录；房间工作区改了以后，Agent 等手上的任务做完才换过去，这期间标记显示「工作区待生效」，没用上工作区时显示「未用工作区」。

会话和游标保存在 Agent 电脑的 `~/.superhive/agents/`，按 Server 地址、房间和名称区分。会话续上不代表上次执行已成功，也不代表中断任务都会自动重跑；详见[任务与恢复](/guides/tasks/)。

### 对话跟着任务走

一个 Agent 在一个房间里不只有一段对话：

- **房间主对话**：人直接 @、主 Agent 接话、定时任务都在这一段里。
- **子任务各一段**：别的 Agent 用 `hive_invoke` 派来的子任务开一段新对话，只带任务说明，不背着房间主对话的上下文。同一个请求方在同一件活里再派来的返修、补充，回执和回复唤醒，以及人直接回复子任务交付的消息，都接着这一段。切到任务目录、回到房间工作区也是按「目录 + 这一段」接回。
- **主对话自动换新**：两件活之间（不是回执、提问的回答或中断续跑，也没有派出去还没回执的子任务），主对话达到约 20 万 token（不超过自动压缩阈值的 0.6），或者空闲超过缓存时长、会话在 10 万 token 以上，就换一段新对话。新对话开头附一份按房间记录拼出来的交接摘要，包括最近交给它的事、人最近说的、它最近的回复、还没回执的子任务和补读方式；任务详情里会写「换了一段新对话」。
- **每轮附带的消息有总量**：默认约 2.4 万 token。触发消息的回复链、@ 了它的、回复它的、它自己发的一定附上，其余从新到旧装满为止；超长的、装不下的只给一行索引，更早的只写范围，需要时用 `hive_room_read` 补读。子任务结果全文每条最多 1.6 万字符，超出给补读指引。

环境变量：`HIVE_TASK_LANES=0` 关掉分道和自动换新，退回一段对话；`HIVE_LANE_RENEW=0` 只关自动换新；`HIVE_LANE_RENEW_TOKENS`、`HIVE_LANE_RENEW_IDLE_TOKENS` 调换新阈值；`HIVE_PROMPT_BUDGET_TOKENS` 调每轮附带消息的总量。子任务分道要服务端也升级，升级前一律按房间主对话处理。

## 上线后先做一次小检查

1. 检查成员列表的精确名称，确认不是仍在启动或已经离线。
2. 发一条低风险请求，例如「请概述你的任务范围，先不要改文件」。有主 Agent 的房间也可由它接收未提及任何人的人类消息。
3. 看消息下方是否从排队进入运行中；若没有，打开调用详情和本机 Agent 日志。
4. 真正派活时写清目标、可写目录、交付文件、验证方式，以及是否允许提交、推送或对外发送。

如果 Agent 不回复，优先核对网络、CLI 登录、名称和消息路由，见[常见故障](/reference/troubleshooting/)。不要为排障公开凭证或无限重启模型。

## 本机设置可以调整什么

在本机 Agent 设置中可查看日志，停止、启动或重启进程，并调整模型、思考强度、Claude 的上下文与缓存、支持的 MCP 和「人发的消息自动引导」开关。自动引导默认关闭；开启前先读[引导与停止的区别](/guides/tasks/)。

### 模型与思考强度

模型和思考强度都按 Agent 单独设置，保存后从下一次回复开始生效，不用重启，也不会改动这台电脑上 CLI 的全局配置。思考强度默认是「跟随 CLI 配置」：不传参数，和没设置时一样。

| 运行时      | 怎么传给 CLI                  | 能选的档位                                        |
| ----------- | ----------------------------- | ------------------------------------------------- |
| Claude Code | 每轮 `--effort`               | low、medium、high、xhigh、max                     |
| Codex       | 每轮 `turn/start` 的 `effort` | 按模型列出（`model/list`），并标出默认档          |
| Copilot     | 每轮 `--reasoning-effort`     | none 到 max，能用哪几档取决于模型                 |
| omp         | ACP 会话的 Thinking 选项      | 按模型列出（`omp models --json`），换模型后跟着变 |

OpenCode、Gemini CLI 的 ACP 会话不提供这个选项，OpenClaw 暂未接入，这几种 Agent 的设置里不显示思考强度。已选的档位当前模型不支持时，设置里会标出来；omp 这一轮按原来的强度跑，并在执行状态里写明原因。失败的任务点「换个模型重试」时，也可以只换思考强度，或者模型和强度一起换，只对这一次生效。每轮实际用的强度会显示在任务详情的「本轮用量」里。

### Claude 的上下文与缓存

Claude Code 的 Agent 设置里多一块「上下文与缓存」，同样从下一次回复开始生效、不用重启：

- **自动压缩**：对话超过这个大小时，Claude 会把前面的内容压成摘要，之后每轮的速度和费用稳定下来，但很早以前的细节只剩摘要。默认 40 万 token（以前接入、没设过的 Agent 也按 40 万），可选 20 万、60 万、80 万或自定义（10 万～200 万）；所选模型的上下文比阈值小时（例如只有 20 万的模型），Claude Code 按模型上限处理，接近上限时压缩，任务详情的「本轮用量」里会写明实际按哪个值压缩；选「不限制，交给 Claude Code」就不传，接近模型上下文上限才压缩。
- **缓存时长**：默认「跟随 Claude Code」。房间的主 Agent 按 1 小时：它两轮之间常隔 5 分钟以上（等子任务回执、等人回复），5 分钟缓存一过期就要整段重写；主 Agent 换人后，下一轮起按新身份算。其它 Agent 由 Claude Code 自动选：订阅额度内一般 1 小时，超出额度或用 API key 时 5 分钟。也可以固定成 5 分钟或 1 小时；1 小时写缓存按输入单价的 2 倍计（5 分钟是 1.25 倍），两轮之间常隔 5 分钟以上时通常更省、更快，偶尔才聊一句的房间反而更贵。

发生自动压缩时，执行状态里会写「上下文已自动压缩（压缩前 → 压缩后 token）」，任务详情的「本轮用量」里也有一行。成员列表里 Claude Agent 的名字旁会显示上一轮结束时的上下文和实际生效的阈值（如 `121k/400k`），以及缓存大约还剩几分钟（从最后一次模型请求算起），悬停看说明；缓存有效期没观测到时不显示缓存，开新话题后清掉。

缓存是 1 小时的（设置里选了 1 小时、主 Agent 跟随 Claude Code，或跟随 Claude Code 时实际写的是 1 小时），Claude 进程一轮结束后也留 55 分钟，否则缓存白留；默认留 10 分钟。同一台电脑上所有 Agent 合起来最多留 8 个空闲的 Claude 进程，超出时把最久没用的结束掉，下一轮照旧接上原会话。已经很大的会话，第一次压缩要整段读一遍再写摘要：实测 70 万 token 的会话，压缩那一轮约 1.5 分钟才出第一个字，之后每轮首字从十几、几十秒降到 4 秒左右。

Codex、Claude Code 的额外 MCP 可选择加载；`hive` 始终加载。MCP 大小和新会话开局 token 是估算，不是精确账单。设置变化按后续回合应用，运行中的工具调用不因取消勾选而撤销；页面提供的重启选项可用于重新启动 Agent。

### Agent 运行时：安装、升级与 CLI 配置

在运行 Hive Server 的这台电脑上打开网页时，「设置」里多一个「Agent 运行时」分类，其他设备看不到：

- **已安装的 Agent CLI**：列出每个 CLI 的版本、最新版、安装位置和安装方式。点「升级」或「安装」会先显示要执行的完整命令，确认后才运行，一次只跑一个。
- **运行时接口地址与密钥**：查看、修改各 CLI 全局配置里的接口地址和密钥，默认打码；改的是 CLI 自己的配置文件，终端里的同一个 CLI 也会受影响。
- **MCP 与技能（统一管理）**：顶上一张表，一行一个 MCP 服务器或 skill，每列一个 CLI。勾上就写进那个 CLI 的全局配置，取消就停用；CLI 不支持停用的（Claude Code 的 MCP）取消时从它的配置里删掉，只剩最后一份时不让删。还没有的 CLI 勾上会先确认，再从已有的那个复制过去（MCP 连同环境变量的值，skill 复制整个目录）。「添加 MCP」可以一次写进多个 CLI。不支持的格子标灰，悬停看原因；点列头跳到那个 CLI 的配置。没有另外的存储，每次都从各 CLI 自己的配置文件读，在 Hive 外手改的也会显示。底部状态栏右侧的「MCP · 技能」显示数量，点开直接进这里；和这一页一样，只有 Server 那台电脑上能看到。
- **CLI 配置里的「技能」**：列出这个 CLI 会读到的全局 skills（名称、描述、来自用户目录、共用目录、插件还是 CLI 自带），可以查看 SKILL.md、启用或停用、删除。
  - 启停用的是各 CLI 自己的开关：Claude Code 写 `settings.json` 的 `skillOverrides`，Codex 写 `config.toml` 的 `[[skills.config]]`，opencode 写 `permission.skill`，Copilot CLI 写 `settings.json` 的 `disabledSkills`，OpenClaw 写 `skills.entries`。原文件先备份。
  - omp 的开关在它自己管理的 `config.yml` 里，网页上只显示状态，要停用请在终端运行 `omp config set skills.ignoredSkills`。
  - 删除前会确认，并把目录挪进同级的 `.superhive-skill-backups/`，需要时可以挪回来。`~/.agents/skills` 这类几个 CLI 共用的目录，确认时会列出还有哪些 CLI 受影响；软链只挪链接本身。
  - Hive 自带的 `superhive` skill 和 Claude Code 插件带的 skill 只能查看：前者用 `hive skill install / uninstall` 管理，后者在 Claude Code 里用 `/plugin` 整个启停。
  - 改动对新开的会话生效，正在运行的 Agent 重启后才读到。
