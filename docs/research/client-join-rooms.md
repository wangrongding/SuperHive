# 客户端加入别人的房间

2026-11-26，rd #6183 / #6212：用户问「客户端怎么加入别人的房间、别人怎么加入我」「拉进来的 Agent 怎么离线、怎么恢复」，以及「浏览器里打开邀请链接能不能直接唤起客户端，在客户端里确认后加入」。这里记录现状、方案对比、选型和安全考虑。实现在 `feat/rd-claude2-client-join-rooms`；后台 join 和「带到别处的 Agent」清单在 rd-claude5 的 `feat/rd-claude5-remote-join-win`，两边按 #6196 约定的接口对接。

## 改之前

- **人加入**：房主生成限时邀请链接 `http://对方:8787/#房间?invite=hvi_…`，对方在浏览器里打开、填名字，换成访客会话。邀请令牌在 hash 里，不进 Server 日志。
- **Agent 加入**：房主（或访客）生成接入命令 `hive join --server … --room … --name … --token …`，在命令行里跑；终端一关 Agent 就掉线。
- **桌面客户端**：只连本机 Hive（`discover`），`will-navigate` 只放行本机 origin，没注册任何链接协议。客户端里没有「连到别人的 Hive」的入口。
- **房主管别人的 Agent**：Server 已经能单独移除访客带进来的 Agent（`DELETE /api/guests/:id`），但网页把入口藏在访客那一行里，而且只有「移除」，没有「暂停」。

## 方案对比

### 人在客户端里进别人的房间

| 方案                                                  | 好处                                               | 问题                                                                               |
| ----------------------------------------------------- | -------------------------------------------------- | ---------------------------------------------------------------------------------- |
| A. 主窗口直接加载对方地址（换掉本机）                 | 改动最小                                           | 主窗口有 preload（终端、选文件、本机房主令牌），把它交给别人的页面等于把本机交出去 |
| B. 主窗口里嵌 `<webview>` / 多个 BrowserView 做标签页 | 像浏览器一样切换                                   | webview 已被我们禁掉（`will-attach-webview`），重新放开面大；标签页 UI 工作量大    |
| **C. 每个外部服务器一个独立窗口（选它）**             | 隔离清楚、实现小；系统的窗口切换天然支持多个服务器 | 多个窗口；用侧栏列表和「文件」菜单补上切换                                         |
| D. 只在系统浏览器里打开                               | 零成本                                             | 用户明确想在客户端里用；浏览器标签容易丢                                           |

选 C，Slack 早期多工作区、Discord 的外部链接窗口也是类似做法。具体：

- 外部窗口**不给 preload**，拿不到终端、选文件、本机令牌；存储放在单独的持久分区 `persist:superhive-remote`，访客凭证只在那个 origin 下，和本机 Hive 的 localStorage 分开。
- 导航、弹窗、重定向都锁在各自的 origin 上（`remoteOrigins` 记每个 webContents 属于哪个服务器，弹出的子窗口继承）；权限只给通知、写剪贴板、全屏。
- 窗口标题写「页面标题 — 对方主机:端口」，一眼看出是别人的服务器。
- 打开过的服务器记在 `userData/remote-servers.json`（最多 30 个，最近打开的在前）。本机页面侧栏底部列出「别人的服务器」，点一下切过去、可以移除；移除会关窗口并清掉那个 origin 的存储。「文件」菜单里也有「加入别人的房间…」（⌘⇧J / Ctrl+Shift+J）和服务器列表。

### 从浏览器唤起客户端（#6212）

| 方案                                                       | 说明                                                                                            |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **自定义协议 `superhive://` + 网页兜底（选它）**           | Zoom、飞书会议、Slack、Figma 的通行做法。Mac 写进 Info.plist，Windows 由客户端写注册表          |
| Universal Links / App Links（https 链接直接归应用）        | 要求服务器域名可控且有 HTTPS 和 `apple-app-site-association`；用户的 Hive 多是局域网 IP，用不了 |
| 本机端口探测（网页去请求 `127.0.0.1:8787` 看客户端在不在） | 会被浏览器的私有网络访问限制拦；还会暴露本机服务给任意网页，不做                                |

流程：

1. 邀请页（还没兑换的访客）先**自动试一次** `superhive://join?url=<当前邀请链接>`，同时有一个明显的「在客户端中打开」按钮。每个邀请链接只自动试一次（记在 sessionStorage），不会反复弹浏览器提示；已经在客户端窗口里（UA 带 `Electron/`）时不试也不显示按钮。没装客户端时浏览器什么都不做（Chrome、Edge）或者提示一次打不开（Safari），页面照旧可以在网页里加入，不会卡住。
2. 客户端收到链接（macOS `open-url`；Windows `second-instance` 的 argv；冷启动时先排队，主窗口起来后再处理），弹**原生确认框**：真实的服务器地址、房间、会用什么身份加入（带邀请时是「访客，进去后填名字，房主可随时移出」）。点「加入」才打开独立窗口，点「取消」什么都不做。
3. `superhive://agent-join?server=…&room=…&name=…&token=…` 不直接接入，而是在本机页面弹「带 Agent 加入」，人选好本机 Agent、看清服务器和名字后点确认才调用接入接口。

浏览器第一次唤起时一定会弹它自己的「是否打开 SuperHive」，网页没法跳过；勾选「始终允许」后不再问。

协议注册：

- **macOS**：`forge.config.cjs` 的 `packagerConfig.protocols` 写进 Info.plist（`CFBundleURLTypes`），装进「应用程序」后 LaunchServices 就认了；主进程再调一次 `setAsDefaultProtocolClient` 兜底。
- **Windows**：Squirrel 安装包不写协议，主进程启动时调 `app.setAsDefaultProtocolClient("superhive")` 写到 `HKCU\Software\Classes\superhive`（当前用户，不需要管理员）。所以装完要先打开一次客户端才能被唤起——Squirrel 装完默认会自动启动一次，正常用户感觉不到。
- **开发版**（`electron .`）不注册，免得抢走已安装客户端的链接。

### 带 Agent 进别人的房间

和 rd-claude5 的 remote-join-win 分工（#6191 / #6196）：

- rd-claude5：本机 Server 的 `/api/local/remote-joins`（列表、创建、停止、启动、删除并退出房间），由 Server 在后台跑 `hive join … --background`，令牌走环境变量不进进程参数；清单存在 `~/.superhive/remote-joins/`，CLI（`hive agents` / `hive leave`）和 Server 读同一份；界面在设置 →「这台电脑」→「带到别处的 Agent」。
- 我：「加入别人的房间」对话框。粘贴邀请链接 → 打开别人的房间；粘贴 `hive join …` 命令或 `superhive://agent-join` → 解析出服务器、房间、名字、令牌，选一个本机 Agent（沿用它的运行时、模型、工作目录、权限档）或者只选运行时，调 POST；409 `REMOTE_JOIN_RUNNING` 提示已经在里面了；接口还没有（旧版 Server 返回 404）时退回显示可复制的命令。成功后跳到「带到别处的 Agent」。
- 别人房间里生成接入命令的地方加了「用客户端带入」链接（`superhive://agent-join…`），点一下交给本机客户端，免得手抄命令。

### 让 Agent 离线和恢复

- **本机 Agent**：已有，成员列表里悬停 → 齿轮 → 设置里的「停止 / 启动」。
- **别人带进我房间的 Agent**：新增「暂停 / 恢复」，和「移出房间」一起放在成员列表里这个 Agent 那一行的「…」菜单里（房主才看得到）。
  - 暂停：会话记 `paused_at`，立即断开它的连接（错误码 `SESSION_PAUSED`）；对方电脑上的进程不退出，照常隔几秒重连、被拒。恢复后下一次重连就回到房间，不用对方重新生成接入命令。
  - 移出：撤销会话（`SESSION_REVOKED`），对方的 Bridge 收到后自己离开这个房间，要回来得重新邀请。
  - 暂停期间不算到期也不算移除；查访问状态时按「已移除」答复，页面不会让它继续用。
- **我带进别人房间的 Agent**：在「带到别处的 Agent」里停止（离线，可再启动）或退出房间（rd-claude5 在对方 Server 加了 `POST /api/guest-agents/leave`，用 Agent 自己的令牌撤销自己的会话）。

## 安全考虑

- **链接一律不可信**：深链接只认 `http:` / `https:`，拒绝带用户名密码的地址；房间名、Agent 名、令牌都按白名单字符校验，不对就什么都不做。确认框里显示的是解析、规范化之后的真实 origin，不显示链接里任何自带的说明文字。
- **令牌**：邀请令牌在 URL hash 里，不发给服务器、不进访问日志；客户端不把深链接写进日志。Windows 上深链接只能通过命令行参数交给客户端（系统机制），但客户端收到后不会再把它放进任何子进程参数；后台 join 的令牌由 Server 通过环境变量交给 `hive join`。
- **过期和撤销**：邀请本身限时，房主可以撤销邀请、移除访客；访客带进来的 Agent 跟着访客的期限走。暂停是可恢复的临时下线，移除是永久的。
- **隔离**：外部服务器的页面没有 preload、在单独的存储分区、导航锁在自己的 origin、权限最小。即使对方页面被篡改，也拿不到本机终端、文件和本机房主令牌。
- **确认**：任何来自外部的「加入」都要人在本机点确认（原生确认框或「带 Agent 加入」对话框），不会被一个链接静默拉进别人的房间。
