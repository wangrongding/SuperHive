## 房间和网页

- **房间**：左侧创建、切换、重命名、归档房间，有未读提示；按住整行拖动可以调整顺序（触屏从左侧「⋮⋮」把手拖，键盘 Alt + ↑/↓），顺序存在这台浏览器里。左侧栏可以收起。
- **房间工作区**：在「管理房间」里给房间指定工作目录，本机 Agent 会在这个房间里切到该目录干活；新建或设置房间时可用目录选择器挑选。工作区在 git 仓库里时，房间名下面显示当前分支（分离 HEAD 时显示短提交号），切了分支 10 秒内跟着变。
- **代码（工作区文件与改动）**：聊天头部的「代码」打开一个可拖宽的只读面板（窄屏全屏），按钮上的数字是未提交改动的文件数。「改动」按已暂存 / 未暂存 / 未跟踪 / 冲突列出文件和增删行数，点文件看 diff：统一视图或左右对照、语法高亮、未改动的部分折叠可展开（「全部展开」一次展开）；房间登记了 worktree 时可以切到某条任务线，默认看它从 base 分叉以来的全部改动（含未提交的），review Agent 的改动就看这里。「文件树」懒加载目录，默认遵守 .gitignore（可勾选显示被忽略的文件），按 git 状态着色，可按文件名搜索、只读预览；「最近提交」可以点开看某次提交改了什么。只读，不能改文件或执行 git 操作；面板打开时每 4 秒刷新改动，关上就不再请求。房主总能看；访客要房主在「管理房间」里打开「允许访客查看工作区文件与改动」（默认关）。.env、私钥、credentials 之类疑似密钥文件只列出、不显示内容，房主确认后才显示，访客始终看不到；路径只能在工作区里，指向外面的符号链接和 .git 目录一律拒绝，服务端日志只记谁看了哪个路径。
- **主 Agent**：房间没有主 Agent 时，第一个上线的 Agent 自动成为主 Agent（等 1.5 秒让同时进来的到齐，本机 Agent 优先，其次按上线先后），房间里发一行不 @ 任何人的系统提示（`kind: "notice"`）；自动设的被删除、移出房间（访客被移除或到期）时顺延给下一个在线的，只是离线不换。房主手动指定或手动取消后记为 `leadMode: "manual"`，自动逻辑不再碰它；「管理房间」里选回「自动」恢复（`PATCH /api/rooms/:id {"leadMode":"auto"}`）。旧库里已设的主 Agent 迁移为手动。也可以在「管理房间」里手动给房间选一个主 Agent。人发的、没有 @ 任何人的消息默认交给它接话，由它自己做，或用 `hive_invoke` 分派给其他 Agent 再汇总；成员列表里它旁边标「主」，输入框提示「不 @ 时交给主 Agent xxx」。带 @ 的消息、回答提问、Agent 之间的消息、回执、定时触发都照旧；回复某个 Agent 的消息（不带 @）交给那个 Agent；未授权访客不带 @ 的消息不交给它。
- **输入框**：刷新后自动聚焦（触屏不聚焦）；为空时用方向键翻看自己发过的消息；发送快捷键、草稿可在设置里调。
- **面板**：右侧有成员、进展两个标签；左侧「提及我」「Agent 任务」「定时任务」面板跨房间汇总相关消息、任务和定时任务，「等你回答」单独分组。消息列表底部「正在处理」列出每个在干活的 Agent，点一下跳到它正在处理的消息。⌘K 搜索消息；⌘P 打开跳转器，跳到房间、Agent 或任务（Tab 切换范围，要你处理的排最前）；⌘J 跳到下一个要你处理的任务；按 ?（输入框里用 ⌘/）查看全部快捷键。
- **需要你处理**：你发起的任务在等你回答、失败、结果未知、做完了（房主还包括等你放行的），不论在哪个房间都会提醒：页面不在前台弹系统通知，点一下切到那个房间并定位到那条消息；页面在前台时右下角弹提示。房间列表上方有「需要你处理」分组（最多 5 条，按等回答、等放行、失败、结果未知、完成未看排序，不改动你拖好的房间顺序）；房间行上的绿色 ✓ 表示有任务做完了你还没看。「设置 → 通知 → 任务提醒」可选系统通知 / 只在页面内（已连飞书或微信时选它，免得两边重复提醒）/ 关闭，需要处理和做完各有提示音。
- **首次使用引导**：第一次在这个浏览器里用的房主会看到三步引导：接入 Agent、打开通知、连上飞书或微信，可以跳过。
- **设置**：界面语言（简体中文 / English）、通知（关闭 / @我 / 当前房间全部）、提示音、主题（亮 / 暗 / 跟随系统）、密度、字号和减少动态效果。
- **新话题**：在对话里插一条分隔线，房间里的每个 Agent 下一轮都丢弃之前的会话、从新会话开始，只把分隔线之后的消息当上下文；旧消息折叠保留，可以展开和搜索。话题聊长了、Agent 开始被旧内容带偏时用它。只有人能开新话题。
- **清空房间**（房间设置里，仅房主及获批管理设备）：删除这个房间的全部消息和 Agent 调用记录，无法恢复；默认同时归档当前白板，历史仍可恢复，Agent 从新会话开始。进行中、阻塞的事项也会一起归档；白板还有仍占用已登记工作区的事项时，整次操作拒绝，不删除聊天或解除占用。取消勾选「同时归档当前白板」可仅清空聊天与调用记录、保留白板；这不代表任务完成或工作区占用解除。

## 邀请其他人（限时）

在 Hive Server 所在的电脑上打开页面的人是房主。其他电脑上的人需要房主邀请才能进入：

- 成员列表下方点「邀请成员」，选择有效期（1 小时 / 12 小时 / 24 小时 / 永久 / 自定义），生成链接后发给任意多人。有效期内谁拿到链接都能加入，每人各用自己的名字。
- 截止时间在创建时就定死；到期后凭这个链接进来的所有人（以及他们带进来的 Agent）会被立即断开、从成员列表消失、再也连不上，已发的消息保留。
- 成员列表里显示每个访客的剩余时间，不到 1 小时会高亮。房主可以给单个访客续期或移除，也可以在邀请弹窗里给整个链接续期或撤销（对凭它进来的所有人生效）。
- 访客只能进入被邀请的房间，不能新建或管理房间、开新话题、追加轮数。访客 @ 房主的 Agent 时，默认要房主点「批准」才会执行（房主的 Agent 可能有本机完全权限）；邀请时勾选「允许对方直接让房间里的 Agent 干活」可免批准。
- 「让对方看到 Agent 的执行过程」开关默认开；关掉后访客只看到精简的状态。
- 访客可以点「带入我的 Agent」生成一条接入命令，在自己电脑上运行。这个 Agent 只能进同一个房间，和访客同时到期或被移除。
- 远程访问拿不到共享接入令牌（`/api/meta` 只把它给本机房主）。房主从别的电脑访问时，用下面的「在其他设备上登录」，或在入口页点「我是房主」粘贴接入令牌。

## 房主在其他设备上登录

在 Server 所在电脑点左下角头像，打开用户菜单里的「在其他设备登录」，点「显示登录二维码」：手机或另一台电脑扫码（或打开链接）后直接以房主身份进入，不用填令牌。二维码 5 分钟内有效、只能用一次，设备要和这台电脑在同一个网络里。

- 每台设备是一个单独的房主设备会话，不会拿到共享接入令牌；「在其他设备登录」弹窗里列出已登录的设备，可以逐个退出。
- 飞书私聊里的推送卡片「在网页查看」和 `/web` 命令带 24 小时登录票，每张票只能登录一次；在别的设备上打开时再发一次 `/web` 取新链接。发到群里的卡片和群里的 `/web` 不带登录票。
- 设备会话最长 30 天，闲置 7 天自动退出。退出一台经飞书登录的设备时，这个飞书连接此前发出的所有登录票一起作废。

登录的设备和本机看到的是同一套界面，包括目录选择器、本机 Agent、保持在线等。区别在于对 Server 所在电脑的操作分了级：

- **查看**：目录、本机 Agent 的列表和状态、MCP 列表、日志、保持在线状态，登录后直接可用。
- **管理**：启动、停止、删除本机 Agent，修改 MCP 和保持在线，清空房间，退出其他设备。设备上点「申请管理这台电脑」，批准卡会推到飞书私聊；也可以在 Server 所在电脑上打开 SuperHive，在弹出的提示里批准。批准后 12 小时内有效，期间每次操作都会推一条提醒到飞书私聊。
- **逐次确认**：用完全权限启动或重启 Agent 时，每次都要再批准一次。批准只对这台设备、这次的配置有效，用一次就作废；重启期间不能改这个 Agent 的设置。
- **已知限制**：逐次确认只覆盖完全权限。获批的设备启动的其他 Agent 也可能在没有沙箱的情况下执行命令，例如 omp 的工作区档不隔离目录，Agent 加载的外部 MCP 也可能执行任意命令。所以「管理权」本身就等于能在 Server 所在电脑上执行命令，批准卡和界面上都写明了这一点，只批准你自己的设备。
- **只限本机**：生成登录二维码、复制总令牌、设置哪些 IM 账号可以批准。在 Server 所在电脑上扫码连接的飞书账号会自动设为可批准。

总令牌也被 Agent 持有，所以拿着总令牌在别处打开的页面不能管理这台电脑，需要扫码登录。手机丢了时，在任一已获批的设备或本机上打开用户菜单「在其他设备登录」，点「全部退出」。房主接入令牌（总令牌）也在这个弹窗底部的「房主接入令牌（高级）」里复制。

## 在飞书或微信里使用

在右侧成员列表下方点「连接 IM」，扫码把飞书或个人微信接进来，之后在手机上就能给房间发消息、收推送：

- **飞书**：用飞书扫码，按页面提示新建或选择一个应用并确认权限。扫码的人就是房主身份，私聊这个机器人发的消息会以你的名义发进房间。
- **个人微信**：用微信扫码并在手机上确认登录。个人微信没有面向第三方的开放平台，这里经腾讯 iLink 通道接入，可能违反平台规则、有被限制或封号的风险，消息内容会经过微信服务器；只支持你本人在私聊里发的文字，默认不启用（`HIVE_IM_WECHAT=0` 可整体关闭）。

在 IM 里：

- 推送的消息顶部标注「房间名 - 发送者」。推送档位可选「与我相关 / IM 任务 / 全部 Agent / 全部消息」，任务结果和状态通知推到房主私聊。你自己派的任务，Agent 发的中途进度也会推，卡片标题是「xx 的进度」。
- 飞书推送是消息卡片：回复、提问、失败、结果未知、待批准、合并推送各有配色和状态标签。提问可以直接点选或勾选作答；失败、待批准、暂停的卡片带重试、批准、继续、忽略按钮，处理后原地更新。从飞书派的任务会回一张进度卡片实时更新。
- 默认接收你所在的所有房间：不在当前房间的卡片标「#房间名」、用橙色（失败仍是红色），底部有「切到 #房间 继续」；直接回复（引用）这张卡片，消息就发到那个房间，不用先切。`/scope current` 只收当前房间，`/scope all` 改回所有房间，控制面板和网页的 IM 弹窗里也能切。微信是文字，开头标「[#房间名]」。
- 不用手打 Agent 名：`/to` 选对话对象（每个房间各记一个），之后不带 @ 的消息自动发给它；回复谁的卡片就发给谁；`@` 简写能唯一匹配时自动补全。不带 @ 时只认开头的完整 Agent 名，避免「code review」之类被误派；都没匹配上、房间又设了主 Agent 时交给主 Agent。
- 常用命令：`/help` 用法、`/who` 谁在忙、`/room` 切换房间、`/level` 推送档位、`/scope` 接收范围、`/lang` 语言、`/to` 对话对象、`/web` 打开网页（仅私聊）。飞书里这些都是带按钮的卡片，也可以用机器人菜单。
- 飞书里图片和文件可以双向收发；微信只支持文字。

## 接入 Agent

### 推荐方式：从网页接入

在右侧成员列表下方点击「接入 Agent」：

1. 选择 Codex、Claude Code、GitHub Copilot、OpenCode、omp、Gemini CLI、Antigravity（agy）或 OpenClaw，再手动点「下一步」；选中不会自动跳步。
2. 选择本机权限档位，再点「下一步」；默认工作区档，完全访问须先明确确认风险。
3. 两种方式任选其一：
   - **在本机启动**：Hive Server 就在你这台电脑上、并且页面是用 `localhost` 或本机 IP 打开的时候可用。可选数量 1–5，按表单显示的名称依次启动同类 Agent；某个创建失败时停止后续创建，已启动的不会回滚。面板里能看到本机装了哪些 CLI、Agent 是否已上线，还能停止、重启、查看日志。房主在其他设备上登录时，启动发生在 Server 电脑，须先取得相应管理授权，高危操作还需单次批准。
   - **复制命令**：到 Agent 所在电脑的终端运行，适合给别人的电脑接入 Agent。命令里已经带好 Server 地址、Agent 名称和 Token，不需要手动拼接。

在本机启动时还可以勾选这个 Agent 加载哪些 MCP（Claude Code、Codex），面板会估算每个 MCP 占用的开局 token；之后在本机 Agent 设置里也能改，下一轮就生效。本机 Agent 设置里还有「人发的消息自动引导」开关（默认关）。

在本机启动的 Agent 会被记住，Server 重启、电脑重启后的恢复见 [本机 Agent 的自动恢复](#本机-agent-的自动恢复)。工作区和完全访问需要指定工作目录：默认就是启动 Hive 服务的那个目录，可以点「选择…」在本机目录树里挑，也可以直接输入（支持 `~/project`）。完全访问没有沙箱，开启前需要再确认一次。从网页启动的本机 Agent 会直接跟随房主给房间设的工作区，不用另加 `--allow-root`。

### 用命令接入

下面是一个 Codex Agent 示例；实际值以网页生成的命令为准：

```bash
npx --yes superhive@latest join \
  --provider codex \
  --access read-only \
  --server http://192.168.1.20:8787 \
  --room general \
  --name frontend-agent \
  --token YOUR_JOIN_TOKEN \
  --persona "你是一名资深前端工程师"
```

可用 provider：

| Provider       | 需要准备                         | 适合场景                     |
| -------------- | -------------------------------- | ---------------------------- |
| Codex          | 已安装并登录 Codex CLI           | 编程、调试、代码修改         |
| Claude Code    | 已安装并登录 Claude Code CLI     | 代码分析和实现               |
| GitHub Copilot | 已安装并登录 Copilot CLI         | GitHub 生态协作              |
| OpenCode       | 已安装 opencode 并配置好模型     | 自选模型（如 GLM、DeepSeek） |
| omp            | 已安装 omp（oh-my-pi）并配置模型 | 自选模型、丰富的内置工具     |
| OpenClaw       | 已配置 Gateway 或 embedded Agent | 自定义工具和自动化           |
| Echo           | 不需要模型 CLI                   | 验证网络、Token 和消息链路   |

那台电脑已经全局安装了 `superhive` 的话，可以把 `npx --yes superhive@latest join` 换成 `hive join`，参数不变。

Provider CLI 必须安装在 Agent 所在电脑，而不是 Hive Server 上。Agent 是一个前台常驻进程，按 `Ctrl+C` 会安全离线；再次运行同一条命令会继续使用本机保存的会话和消息游标。

不指定 `--room` 时，Agent 会加入服务器上所有未归档房间，并为每个房间保持独立会话和消息游标，新建、归档房间也会自动跟随；指定 `--room general` 可以限制为单个房间。命令接入的 Agent 默认只在 `--cwd` 及其上一级里跟随房间工作区，要去别的目录用 `--allow-root PATH`（可重复）。只读档也跟随房间工作区（能读不能写；OpenClaw 除外，它的权限 Hive 管不了）。每一轮的规则里写明「本房间工作区」和「你当前的工作目录」，没用上工作区时写明原因；成员列表里 Agent 名字旁的「目录」标记悬停可看实际工作目录，工作区改了但 Agent 还在忙时显示「工作区待生效」，等它空闲后换过去（单房间 `--room` 模式也一样）。完整参数见 `hive join --help` 或 [开发者文档里的 CLI 参数](development.md#cli-参数)。

### 让终端里单独跑的 Agent 学会接入

`hive --skill` 会打印一份给 Agent 读的协作说明（SKILL.md）：怎么用 `hive join` 接入、能用哪些工具、房间规则是什么。推荐直接装进 Claude Code、Codex、OpenClaw 这些支持全局 skills 目录的 Agent，之后升级重跑一次即可：

- 装进本机检测到的所有 Agent（claude、codex、openclaw）：

  ```bash
  hive skill install
  ```

- 只装指定的一个：

  ```bash
  hive skill install codex
  ```

- 查看各 Agent 装的版本：

  ```bash
  hive skill status
  ```

- 没全局安装时用 npx：

  ```bash
  npx --yes superhive@latest skill install
  ```

装好的文件带托管标记，`hive skill install` 会原地更新版本，`hive skill uninstall` 移除；如果目录里原来有一份手写的同名 SKILL.md，会先备份成 `SKILL.md.bak` 再接管，`hive skill uninstall` 时再放回原处。仓库公开后也可以用 `npx skills add wangrongding/SuperHive --skill superhive -g` 安装。

### Agent 权限

命令行 `hive join` 默认只读，网页「接入 Agent」默认工作区档；提升权限必须由 Agent 所在电脑的操作者显式选择：

| 档位        | 能做什么                                                       | 额外要求                                                          |
| ----------- | -------------------------------------------------------------- | ----------------------------------------------------------------- |
| `read-only` | 默认安全模式；不写入工作区，Provider 使用只读/规划策略         | 无；默认使用该 Agent 专属的空目录，房间设了工作区时在工作区里只读 |
| `workspace` | 在指定工作目录内写文件和运行命令                               | 必须指定 `--cwd /absolute/path`                                   |
| `full`      | 移除 Hive 配置的沙箱和审批限制，拥有当前系统用户能做的全部操作 | 必须指定 `--cwd`；高风险                                          |

例如，只允许 Agent 操作一个项目：

```bash
npx --yes superhive@latest join ... \
  --access workspace \
  --cwd /absolute/path/to/project
```

`workspace` 档下支持审批的 Agent 执行中要做超出许可的事（Codex 想在沙箱外执行命令或改文件、OpenCode 请求改工作区外的文件、Claude Code 遇到要确认的工具），会以提问的形式发给任务的发起人，只有「允许 / 拒绝」两个选项：网页上点选、回复这条消息「允许」或「拒绝」、或在飞书卡片上点都可以，结果直接交回正在执行的这一轮。只有房主（或自己带入这个 Agent 的有效访客）能批；10 分钟没人批、这一轮结束或被停止、Server 重启都按拒绝处理；带条件的回复（如「可以，但先别删」）不算批准。`read-only` 档照旧直接拒绝相应越权请求，`full` 档不走这类工具询问；普通业务决策仍可向人提问。

omp 不会把写入限制在工作目录内，它的 `workspace` 只是在只读工具之外再开放编辑、写文件和 Shell；需要目录隔离时请选择 OpenCode、Codex 或 Claude Code。

Hive Server 只转发消息，不提供远程 Shell。`workspace` 和 `full` 的实际风险来自 Agent 所在电脑上的 Provider 权限，请只在信任的房间和目录中开启。

### 本机 Agent 的自动恢复

在网页上「在本机启动」的 Agent，配置和「是否该运行」都存在 Server 的数据库里：

- **Server 重启**（`hive restart`、`hive stop` 后再 `hive start`、开发时代码换代）：没被你手动停止的本机 Agent 会自动拉起；手动停止过的保持停止。上一个 Server 交接时还在跑的进程直接接管，手上的任务不中断：`hive restart`、`hive update` 默认就走交接（旧 Server 退出前写交接标记，不结束本机 Agent；新 Server 按数据库里记的进程号接管）。交接不了（旧版 Server、换了端口或 Join Token、关掉本机 Agent）又有 Agent 在干活时，终端里先问你等它们做完还是立即重启，脚本里等它们做完（最多 30 分钟），`--wait` / `--force`（`hive update` 是 `--force-restart`）跳过询问。需要重新拉起多个 Agent 时逐个错开约 2 秒，不会同时启动一堆 CLI 抢 CPU 和登录态。
- **会话续上**：每个 Agent 在本机状态目录（`~/.superhive/agents/`）里按「Server 地址 + 房间 + 名字」保存会话和消息游标，重新拉起后接着原来的会话，只读取上次处理之后的新消息。
- **对话跟着任务走**：房间主对话（人 @、主 Agent 接话、定时任务）和每件子任务（别人 `hive_invoke` 派来的，含同一件活的返修、回执、回复唤醒，以及人直接回复子任务交付）各用一段会话，按「目录 + 道」收起和接回，最多留 16 段。主对话在两件活之间达到约 20 万 token（不超过压缩阈值的 0.6），或空闲超过缓存时长且在 10 万以上时换新，新会话开头附按房间记录拼的交接摘要。每轮附带的公共消息默认约 2.4 万 token，回复链、@ 了它的、回复它的、它自己发的必带，其余从新到旧装满，装不下的给索引和补读方式；子任务结果全文每条最多 1.6 万字符。`HIVE_TASK_LANES=0` 全部关掉，`HIVE_LANE_RENEW=0` 只关换新，`HIVE_LANE_RENEW_TOKENS` / `HIVE_LANE_RENEW_IDLE_TOKENS` / `HIVE_PROMPT_BUDGET_TOKENS` 调阈值。方案见 [task-scoped-sessions](research/task-scoped-sessions.md)。
- **电脑重启或关机**：系统关机时 Server 会让本机 Agent 正常离线，「该运行」的标记不变。电脑开机后要有人启动 Server，Agent 才会跟着回来：运行一次 `hive start`，或用 `hive autostart on` 让 Server 在登录后自动启动（见下文）。
- **关机或崩溃时正在执行的任务**：若留有中断执行记录、本轮未记录可能有副作用的步骤、旧运行时进程已退出、原消息和调用仍可恢复，重新连接后会按原消息自动重新执行，最多 2 次，并标注「自动恢复第 N/2 次」。写文件、发消息、白板更新、未知命令或外部工具等可能有副作用；不满足条件的通常标为「结果未知」，交给你核对。已停止、撤回、收起或落定的调用不再自动排队；这不是保证从写入断点继续。
- **Server 被强制结束**（kill -9、崩溃）：Server 拉起的 Agent 会发现 Server 不在了，宽限期内没有新 Server 接管就自行离线退出，不留占着名字的孤儿进程；下次 Server 启动时照常恢复。
- **反复启动失败**（比如 CLI 没登录）：10 分钟内意外退出 5 次就停止自动重启，面板里显示最后的报错；修好后点「启动」。
- **代码更新后自动用上新代码**：跑着的 Agent 进程用的是它启动时的那份代码，合入新提交、`git pull` 或 `hive update` 之后要重启才会用上新代码。Agent 加入房间时会上报自己的版本：npm 安装报包版本；源码运行还会带上启动时的提交，以及 `packages/superhive`、`packages/protocol` 两个目录的 git 树指纹，只改网页或文档的提交不算 Agent 变旧。成员列表里，落后的 Agent 名字旁会标「旧版本」。「设置 · 这台电脑 · 本机 Agent」里能看到每个 Agent 的版本、是否正在执行任务（任意房间）。「代码更新后自动重启」默认打开：落后的 Agent 等手上没有排队、执行中的任务时自动重启一次，正忙的跳过，空闲后再试。每次只重启一个，同一个版本只自动重启一次，同一个 Agent 两次自动重启至少隔 10 分钟。
- **手动重启**：「重启」默认等它手上的任务都做完再重启，正在做的事不会被打断；「立即重启」要先确认，正在执行的任务会被中断，结果交你核对。

## 让 Agent 干活

### 跟踪、停止和重试

每次 `@agent` 都会在消息下方显示一个状态：排队中 / 已送达 / 运行中 / 已完成 / 失败 / 被拦截 / 结果未知 / 已停止。排队中会写明前面还有几个、派出多久还没确认收到；调用详情里的「为什么是这个状态」说明依据（离线、排在谁后面、多久没有新事件、最后一步是什么）。

- **执行过程**：运行中状态行显示 Agent 当前这一步（比如「运行 git status」）；点「详情」能看实时滚动的执行过程（思考、跑的命令、改的文件、中途说的话），Claude、Codex、opencode、omp 支持。执行过程只放在内存里，结束后保留到刷新为止，不落库、不发 IM。
- **中途进度**：预计要做很久（比如超过 5 分钟）的任务，Agent 开工先发一条「进度」说打算怎么做、大概多久，之后到了阶段完成、发现和预期不一样、有中间产物这类节点再发，带蓝色「进度」标签、正文淡显。你直接派的任务每个最多 3 条，Agent 之间委派的 1 条；进度不算最终回复，结论照常单独发。
- **引导**：Agent 忙的时候，新消息默认排队。你可以在排队中的消息上点「引导」，或在输入框旁直接点「引导」发出，用这句话引导它正在做的事：Agent 在工具调用的间隙读到它（Claude Code、Codex、opencode、omp 支持）；「停下当前，改做这条」会先停掉正在做的，再单独做这条。只对人直接发的消息有效。
- **停止**：运行中的任务可以随时停止。Codex、OpenCode 和 omp 会中断当前回合（Agent 进程保持运行），能确认停下就显示「已停止」；Claude Code 会先请它自己中断当前回合（停掉正在跑的工具），确认停下后显示「已停止」（这个 Claude 进程随后结束，下一轮新起），可以直接重试，5 秒内没确认才结束进程、按「结果未知」处理；Copilot 和 OpenClaw 会结束对应的子进程。对已经结束的一轮点停止会立即答复。Agent 把几条消息合在一轮里做时，在其中任意一条下面点「停止这一轮」会把这一轮一起停下；访客只能停自己发起的，同一轮里还有别人发起的消息时按钮点不了，悬停会说明原因。
- **撤回**：撤回自己的消息时，如果这条消息派出的任务还没结束，确认里默认「撤回并停止」：排队中、被拦下的直接取消，执行中、等你回答的按「停止」处理，状态写成「消息已撤回，已停止」，不算需要你处理；也可以选「只撤回」，让正在做的照常做完、只是不再回复。只停这条消息直接派出的任务，它们再用 hive_invoke 派出去的子任务不连带停；Agent 把这条和别的消息合在一轮里做时，这一轮会继续把其他消息做完，这条显示回执行中并写明「这一轮会继续」，这一轮结束后标为已停止。已经改的文件、跑过的命令不会撤销。
- **重试**：失败、已停止的调用可以一键重试；「结果未知」要你先核对实际做到哪一步，已做过的文件、提交或外部操作不会撤销。崩溃或强制结束后的自动恢复只有满足上述严格条件才进行，最多 2 次，不是所有中断都重跑。
- **上游出错自动继续**：模型服务限流、过载、5xx、断流时，这一轮如果还没做过有副作用的操作，等 1 分钟、3 分钟后接着原会话自动继续；做过改动或次数用完就标失败并写明原因，状态行按钮显示「继续」，点一下接着原会话往下做。Claude Code、Codex 支持。
- **合并处理**：Agent 忙的时候陆续收到的 @ 会合并成一轮回应。
- **睡醒保护**：检测到系统睡眠后的时间跳变，心跳先给一轮宽限，运行中任务扫描给约 2 分钟恢复时间，避免刚醒来就把所有 Agent 判离线或任务判为结果未知；之后仍按正常规则检查，不保证所有运行时或网络都能恢复，也不补跑已错过的定时执行。
- **防止 Agent 互相刷屏**：只拦真正的死循环，不拦正常推进。用 `hive_invoke` 派活、收回执、再派活的委派链不限深度、不限条数，来回多少轮都不会被拦。会被拦的是：两个 Agent 没人插话、也没有附件或白板更新，连续互相 @ 超过 8 条（各说 4 次，一问一答、review 来回改两轮都在这以内）；自上次有人发言以来，Agent 普通 @ 连续超过 50 条（派活、回执、进度和被委派方的答复不算）；同一对 Agent 每天经普通 @ 互相唤醒超过 100 次；单个 Agent 每分钟发言超过 12 条（服务端代发的回执不算）。前三种会显示为「被拦截」，点击「继续 10 轮」即可放行，你下次发言后恢复默认；每分钟条数到顶时稍等一会儿就能接着发。
- **允许不回复**：Agent 只在需要对方回应或接手时才 @ 对方，单纯提到时直接写名字；被其他 Agent 的告知、附和唤醒时可以只输出 `NO_REPLY`，Bridge 不会发送任何消息，状态显示为「已完成 · 无需回复」。人类直接 @ 的问题仍必须回复。升级或修改角色后，规则会在下一轮立即重新注入，不必等新会话。

## 协作：委派、白板、提问、定时、跨房间

- **委派子任务**：Agent 之间用 `hive_invoke` 委派，子任务结束后结果自动回执给委派方。调用状态行和「调用详情」显示谁委派了谁、子任务进度和回执状态，「Agent 任务」列表里也能看到。
- **进展**：右侧栏「进展」是给人看的一面，只分三组、每条一句话：**等你处理**（Agent 在等你回答、等你放行或决定继续）、**在做**（进行中、做完等验收的，以及白板上标了阻塞的，阻塞多半卡在外部或别的 Agent，标「卡住了」）、**最近完成**（里程碑，分支合入后自动转来的标「已合入」）。点一条跳到聊天里对应的那段讨论（Agent 登记时正在处理的那条消息）。这一句取自白板摘要的第一句，所以规则要求 Agent 写白板时先用一句人话说清是什么事，细节放后面。
- **协作白板**：「进展」最下面默认折叠的「Agent 白板（原文）」。Agent 用 `hive_board_update` 按同一个 `key` 推进事项，按「阻塞 / 进行中 / 已就绪 / 里程碑」分栏展示。登记了分支的进行中、已就绪条目，在后台扫描发现分支已合入（分支上有过提交，进行中的还要求目录干净）后自动转成里程碑；同一个合入提交只转一次，Agent 重新登记会以它的为准。里程碑 3 天没更新自动归档，可在历史里恢复。默认「当前事项」支持状态筛选；房主可勾选不再用于当前协作的成果，批量归档（每次最多 200 条），在「历史归档」中单条或批量恢复。待 review 的成果请保留；仍有登记工作区占用的事项不能归档或删除；Agent 崩溃或忘记收尾留下的进行中、阻塞旧条目，房主可以直接归档。历史不计入当前数量，也不进入 Agent 白板摘要；`hive_board_read` 每栏最多返回 50 条当前事项，更多记录和归档需在网页查看。白板不会按时间或数量自动删除（只有上面说的里程碑自动归档）；更新已归档事项的同一个 `key` 会恢复它。永久删除仅在历史视图提供，需确认且不可恢复。换话题、仅清空聊天保留当前白板及其归档；清空房间默认归档当前白板，受保护的 worktree 占用会阻止清空，不能用它绕过安全清理。
- **向人提问**：Agent 需要人拍板时用 `hive_ask_human` 提问；需要你在外部系统里点一下、扫码、登录、接管，要你提供凭据，或要做没交代过的不可逆、对外、花钱的操作时，必须立刻提问，不等一轮做完。提问可以带 2–10 个选项（单选或多选），网页渲染成可点选的按钮，最后固定一行「其它」可自由填写；没有选项的点提问下方的「回答」。回答后服务端带着答案重新唤醒提问的 Agent，不用再 @ 它。隔了很久才回答也没关系：回答气泡顶上会显示「回答提问 #N」卡片，点了跳回原提问；Agent 那边会收到这条回答对应哪一问和提问原文，不会按最近的话题去猜。
- **定时任务**：「X 点提醒、检查、执行」这类事，Agent 用 `hive_schedule_create` 登记定时任务，到点服务端以发起人名义发一条「⏰ 定时任务」消息唤醒它；左侧「定时任务」面板能看到所有房间的定时任务（可以按房间筛选，点房间名跳过去）并取消；入口上的数字是待执行的个数，有新的失败或错过时另外用醒目的颜色标出。Server 没运行、晚于 10 分钟才轮到的标为已错过，不自动补跑。要重复执行（比如每 5 分钟检查一次），创建时给间隔和结束时间登记成周期任务：服务端每次到点自己登记下一次，最短 5 分钟一次、最多 288 次；上一次还没做完时这一次自动跳过；在面板里点「结束周期」或让 Agent 取消待执行的那一次，整个周期就结束。
- **新建房间、跨房间派活**：在你本人发起的任务里，Agent 可以替你新建房间（可带工作区，`hive_room_create`），也可以到别的房间以自己的名义 @ 那边的 Agent 派活（`hive_room_post`，说房间 ID 或显示名称都行），消息末尾注明从哪转来；结果留在那个房间。访客发起的、Agent 之间的任务不能用。

## 图片和文件附件

在输入框里直接粘贴截图、把文件拖进输入框，或点左下角的 📎 选择文件，都会先上传、显示进度，可以移除或重试；上传完成后和文字一起发出，也可以只发附件。单个文件不超过 20 MB，一条消息最多 10 个、合计 50 MB。

- **预览**：PNG、JPEG、GIF、WebP 在消息里显示缩略图，点开看大图（多张可左右切换、可缩放）；Markdown 按格式渲染，代码和文本按扩展名高亮，PDF 用浏览器自带的查看器内嵌查看，预览里可以下载。HTML、SVG 只当源码显示，不会执行；其他文件（zip 等）点击下载。
- **Office 文档**：Word（docx）分页显示、保留版式；Excel（xlsx / xls）和 CSV 按工作表分 tab，列名和冻结的表头固定在上面，数字、日期按单元格格式显示，合并单元格和列宽保留，大表只读前 1 万行、显示前 200 列；PowerPoint（pptx）逐页看，可以点缩略图或按方向键翻页，也能全屏放映。文件只在浏览器里解析，不上传到任何在线预览服务；渲染结果放在不能执行脚本、不能联网的隔离框里，文档里的宏、脚本和外部链接都不会生效。超过 50 MB、设了密码或解析失败的，会说明原因并给出下载。「产物」详情栏和「代码」面板（文件树预览、二进制改动的改前改后对照）用的是同一套预览。旧版 .doc / .ppt 不支持，请下载查看。
- **权限**：附件只有所在房间的成员能读；撤回消息后附件随之失效；上传后 24 小时没发出的会被清理。

Agent 读附件有两条路，都不需要把文件内容塞进聊天：

- **Hive MCP 工具 `hive_attachment_read`**：所有接入了 Hive MCP 的 Agent 都能用，文本分段返回，图片以图片内容返回。
- **本地路径**：各档（含只读）的 Agent，Bridge 都会在提示里给出附件的本地路径，下载是 Bridge 做的，Agent 只是用读文件工具打开。与 Server 在同一台电脑上的房主 Agent 直接用 Server 存的那份，不重复保存；远程或访客带入的 Agent 由 Bridge 用自己的凭证下载到本机缓存（`~/.superhive/agents/attachments/`）并校验 SHA-256。文件工具只能碰工作区的运行时（Copilot、Gemini CLI、OpenCode、agy）一律下载到这个缓存目录，并且只放行这一个目录（Copilot `--add-dir`、Gemini `--include-directories`、OpenCode `external_directory`），只读档照旧不能写、不能跑命令。Hive MCP 连不上时，这是 Agent 看到附件的唯一途径。

Agent 连不上 Hive MCP 时（例如 0.4.4 及更早版本里 Agent 名字带中文），它会少了全部 `hive_*` 工具：读不到附件、看不到白板、不能委派，回复仍由 Bridge 代发，表面看不出来。现在 Bridge 从运行时的启动信息里发现后（Claude Code、Codex 能报，ACP 类运行时和 Copilot 不报），成员列表里这个 Agent 名字旁会显示红色的「工具未连上」，悬停能看到原因；连上后自动消失。

Agent 要把生成的文件交给大家，在最终回复末尾加一段声明，Bridge 会把文件上传成附件随回复发出：

```text
<hive-attachments>
output/result.png
</hive-attachments>
```

文件的读取和上传都在 Agent 所在的电脑上完成，Server 不会按路径读盘。只读 Agent 不能发布文件；其它权限只能发布工作目录（`--cwd`）内的普通文件，符号链接指到目录外也会被拒绝；没发出的会在回复末尾写明原因。声明只在 Bridge 代发的最终回复里生效，用 `hive_message_send` 发送时不附带。

已实测：Claude Code（只读与 workspace）能经 MCP 工具看图、读文本，只读档（plan 模式）和 workspace 也都能用 Read 打开工作区以外的本地路径；Codex workspace 经 MCP 工具只拿到图片元数据，改用 `view_image` 打开本地路径后能看图。只读档读工作区以外的图片：omp 直接能读；Copilot、Gemini CLI、OpenCode 不放行时读不到（Copilot 读不到时还会凭文件名瞎猜），放行缓存目录后都能读到。能否看懂图还取决于模型本身是否支持图片。

## 模型与思考强度

本机 Agent 设置里可以按 Agent 选模型和思考强度，写进这个 Agent 的设置文件，下一轮生效、不用重启，也不改 CLI 的全局配置。思考强度默认「跟随 CLI 配置」（不传参数）。Claude Code 每轮传 `--effort`，Copilot 传 `--reasoning-effort`，Codex 在 `turn/start` 里带 `effort`（会沿用到后续回合，所以「换个模型重试」只换一次时，下一轮会显式改回会话原来的强度），omp 切 ACP 会话里 category 为 `thought_level` 的选项。档位由 `hive models --provider X --json` 给出：Codex、omp 按模型列出，其余按 CLI 接受的全部档位。OpenCode、Gemini CLI、OpenClaw 不支持，设置里不显示。失败任务的「换个模型重试」可以只换思考强度，访客不能指定（花的是房主的额度）。

Claude 还有「上下文与缓存」两项，只对 Claude Code 显示：自动压缩阈值默认 40 万 token（没设过的老 Agent 也按 40 万；可选 20 万、60 万、80 万、自定义 10 万～200 万，或「不限制」不传；模型上下文比阈值小时 Claude Code 按模型上限压缩，本轮用量里记下传的阈值并按 contextWindow 写明实际生效的值），缓存时长默认跟随 Claude Code：房间的主 Agent（房间设置里的 `leadAgent`，Bridge 建立时从房间信息拿到，之后按 `rooms.changed` 和多房间模式每分钟的对账更新）传 `1h`，主 Agent 换人后下一轮按新身份；其它不传，Claude Code 自己选（订阅额度内一般 1 小时，超出额度或 API key 时 5 分钟），可固定 5 分钟或 1 小时。两项和沙箱设置合在一个 `--settings` 里传（`autoCompactWindow`、`promptCacheTtl`），本机实测 Claude Code 2.1.330 在 `--print`、stream-json、常驻进程里都生效，压缩后照常 `--resume`。Claude Code 自动压缩时（`system/compact_boundary`，`trigger: auto`）Bridge 在执行状态里写「上下文已自动压缩（压缩前 → 压缩后 token）」，并把压缩前后大小、用时记进本轮用量。

Claude Code 的进程在一轮结束后保留 10 分钟，下一轮直接把消息写进去，不再拉起进程、加载 MCP、读取会话记录（`--resume`），Mac 上每轮省 1 秒左右，会话记录大时省得更多；规则、模型、思考强度、MCP、权限档变了，或要接的不是这个会话（开了新话题），就结束它另起（压缩阈值、缓存时长变了也算）；出错、被停止、空闲超时也会结束。环境变量 `HIVE_CLAUDE_KEEPALIVE_MS` 调保留时长，`0` 表示每轮新起进程。缓存是 1 小时的（设置里固定 1 小时、主 Agent 跟随 Claude Code，或跟随 Claude Code 时这一轮实际写的是 1 小时）进程留 55 分钟（不短于 `HIVE_CLAUDE_KEEPALIVE_MS`）。同一台机器上所有 Bridge 合起来最多留 `HIVE_CLAUDE_MAX_WARM`（默认 8，`0` 不限）个空闲 Claude 进程：停下时在 `$TMPDIR/superhive-claude-warm-<uid>/` 登记，超出就删掉最久没用的登记，它的 Bridge 每 5 秒查一次，发现登记没了就结束进程（下一轮照旧 `--resume`）；Bridge 已退出的登记顺手清掉。

用量里还记这一轮最后一次请求的上下文（`lastContextTokens`）、传的压缩阈值（`compactWindow`）和缓存有效期（`cacheTtlMs`：这一轮写了缓存按写入类型，只读了按上一轮的）。Server 据此给成员信息加 `context`（上下文、阈值、模型窗口、`cacheExpiresAt` = 最后一次请求 + 有效期），成员列表显示 `121k/400k · 缓存 46 分`，开新话题或清空房间时清掉。

## 用量和费用

Bridge 记录 Agent 每轮的真实用量（这一轮传了思考强度时一并记下，任务详情「本轮用量」里显示）（Claude Code 的 stream usage、Codex 的 tokenUsage；agy 等 ACP 运行时在回合结束时给总用量，一并记下会话当前的模型和思考强度，请求次数和会话大小是估算），失败、被停止和结果未知的轮次也照常记账（ACP 运行时只有正常结束的轮次有用量）。「Agent 任务」面板和用量统计里能看到每轮的 token、缓存命中率、会话大小、估算费用和大额缓存写入；缓存没命中时区分观测到的原因和推测的原因，会话偏大时提醒开新话题。token 数取自 Runtime 返回的真实用量，费用为估算，以模型服务的账单为准；尚未接入用量采集的 Runtime 会显示没有记录。

## 故障单和慢操作

Server 和网页本身出的问题会自动记成故障单。在 Server 所在电脑上以房主身份打开页面时，左侧「搜索 / 提及我 / Agent 任务」下面多一个「故障」入口，其他人和其他设备上看不到：

- **故障单**：失败先分清是谁的问题。模型服务、网络、凭证、Agent 自己的 CLI 崩溃这类外部原因只重试和提示；我们自己的问题按同一种错误合并计数，可以手动派修、标为已解决或忽略。Agent 提的补充规则在这里批准或拒绝，修完记下的经验也在这里看。
- **慢操作**：Server 上的任务目录锁、git 命令、重查询和请求超过阈值时记在这里，页面卡顿、Agent 起不来时用来排查。只存在内存里，重启后清空。

入口上的数字是还没人管的故障单和待批准的规则提议，没有就不显示。修失败 2 次、改到受保护代码而升级给你的故障单，以及待批准的规则提议，还会出现在左侧「需要你处理」里，点一下直接打开那一条。

自动派修默认关闭，在左侧「故障」面板顶部点「派修设置」展开后打开，从下拉里选在哪个房间派活、由哪个 Agent 修、谁来 review，再调出现几次派修、每天最多派几次、修失败几次找你；改了就自动保存，派活消息以你的名义发出。打开后同一种问题出现到次数，就派 Agent 先写复现测试再修，合入照样要经过 review。

## 熄屏后保持在线

「设置 → 这台电脑」里可以让电脑熄屏后不进入睡眠，飞书消息和 Agent 任务不会中断：连着 IM 时（默认开，包括正在重连）或有 Agent 任务在跑时（默认关）阻止系统空闲睡眠，屏幕照常熄灭；默认只在接电源时生效。macOS 用 `caffeinate -i`，Windows 用 `SetThreadExecutionState`，其它系统显示不支持。生效时房间标题下有「☾ 保持在线」标签。只有本机房主能改这项设置。合盖睡眠不在覆盖范围内。

## 停止、重启、更新和开机自启

推荐全局安装 `superhive`（`npm i -g superhive`，要求 Node.js 22.12 或更高），平时都用 `hive` 命令：

- 启动 Server 并打开网页，等同 `hive start`：

  ```bash
  hive
  ```

- 停止，也可以写 `hive off`：

  ```bash
  hive stop
  ```

- 重启，沿用原来的 `host`、`port` 和 `public-url`：

  ```bash
  hive restart
  ```

- 更新到最新版；Server 正在运行就自动用新版本重启：

  ```bash
  hive update
  ```

- 只检查有没有新版本，不安装：

  ```bash
  hive update --check
  ```

重启时也可以覆盖配置：

```bash
hive restart --port 9000
hive restart --public-url https://hive.example.com
```

常用启动选项：

```bash
hive --port 9000
hive --public-url https://hive.example.com
hive --data-dir /srv/superhive
```

- 在当前终端运行，直接看日志：

  ```bash
  hive --foreground
  ```

- 关闭网页上的「在本机启动」：

  ```bash
  hive --no-local-agents
  ```

- 启动后不自动打开浏览器：

  ```bash
  hive --no-open
  ```

`hive start` 默认会用浏览器打开本机网页（`http://127.0.0.1:8787`，房主身份）；SSH、CI、没有图形界面或 `BROWSER=none` 时不打开。`restart` 默认不再新开标签页，要打开加 `--open`。

### 更新

- `hive update` 先查 npm 上的最新版，再用你当初安装 `superhive` 的那个包管理器（npm、pnpm、bun 或 yarn 全局安装，自动识别）装到最新版。Hive Server 正在运行的话，装好后自动用新版本重启，沿用原来的启动配置；重启时本机 Agent 不下线，正在跑的任务继续做完（见上文「Server 重启」）。已经是最新版会直接说明。
- 平时在终端运行 `hive` 时会顺便检查一次有没有新版本：最多等 1.5 秒，查不到不影响使用，结果缓存 1 小时。有新版会提示运行 `hive update`。设置环境变量 `NO_UPDATE_NOTIFIER=1` 可以关闭这项检查。

### 不想全局安装：用 npx

把上面的 `hive` 换成 `npx superhive` 即可，例如 `npx superhive`、`npx superhive stop`、`npx superhive --port 9000`。用 npx 运行时 `hive update` 不适用，更新改用：

```bash
npx superhive@latest restart
```

`hive` 是 npm 包 `superhive` 提供的命令；用 `pnpm link --global` 链接源码时同样可以用 `hive`。

### 开机自动启动

- 登录后自动在后台启动 Hive Server：

  ```bash
  hive autostart on
  ```

- 指定启动配置：

  ```bash
  hive autostart on --port 9000 --public-url https://hive.example.com
  ```

- 看是否已开启：

  ```bash
  hive autostart status
  ```

- 关闭：

  ```bash
  hive autostart off
  ```

- macOS 写入 `~/Library/LaunchAgents/dev.superhive.server.plist`，Linux 写入 systemd 用户服务 `~/.config/systemd/user/superhive.service`，Windows 在「启动」文件夹里放一个 `SuperHive.vbs`，以隐藏窗口启动，登录时不会闪出命令行窗口（旧版本写的 `SuperHive.cmd` 会在重新开启时换掉、关闭时一起删除）。都只对当前用户生效，不需要管理员权限。
- 不写 `--host`、`--port`、`--public-url`、`--no-local-agents` 时，沿用正在运行的 Server 的启动配置（所以最好在 Server 运行时开启）；Server 没在运行时用默认配置。
- 开机后 Server 起来，网页上启动过、没手动停止的本机 Agent 会跟着逐个恢复（见 [本机 Agent 的自动恢复](#本机-agent-的自动恢复)）。
- 自启动记下的是当前这份 `superhive` 的 node 和脚本路径。用 `npx` 临时运行时，这份文件在 npm 缓存里，清缓存后会失效；建议先 `npm i -g superhive` 再开启。`hive update` 原地更新，路径不变，一般不用重新开启；换了 Node 版本管理器或全局安装目录后再运行一次 `hive autostart on`。
- 自启动不会打开浏览器。

## 局域网和公网

- 局域网：浏览器和 Agent 访问同一个局域网地址，例如 `http://192.168.1.20:8787`。
- 防火墙：首次监听时允许 Node.js 接受私有网络连接；访客 Wi-Fi 可能启用客户端隔离。
- 公网：建议使用反向代理提供 HTTPS/WSS，并设置 `--public-url https://hive.example.com`。Token 是共享 Join Token，不是完整账户系统；公网部署请额外配置访问控制。
- HTTP 局域网也支持网页的命令复制；公网部署仍建议使用 HTTPS。

浏览器和 Agent 只需要能访问 Hive Server，不需要参与者之间互相直连。

## 常见问题

### 页面打不开

确认 Server 仍在运行、端口没有被防火墙拦截，并让浏览器访问启动输出里的实际地址。局域网设备不能访问 `localhost`，需要使用运行 Server 电脑的局域网 IP。

### 复制命令没有反应

先升级到最新版本：

- 全局安装时：

  ```bash
  hive update
  ```

- 用 npx 运行时：

  ```bash
  npx superhive@latest restart
  ```

当前版本在 HTTPS/localhost 使用 Clipboard API，在局域网 HTTP 使用兼容复制；若浏览器策略仍禁止复制，命令区会提示手动复制。

### 两个标签页提示用户名冲突

同一个人类用户名可以在多个标签页同时在线。若仍出现旧提示，请先 `hive update` 更新到最新版，再刷新两个标签页。同名 Agent 不能重复在线；请为不同 Agent 使用不同的 `--name`。

### Agent 没有回复

确认：

1. Agent 终端进程仍在运行，没有退出或报错（本机 Agent 在「本机 Agent」面板里看日志）。
2. Agent 所在电脑可以访问网页显示的 Server 地址。
3. Token、`--name` 和 provider CLI 登录状态正确。
4. 消息中使用了精确的 `@agent-name`（或房间设了主 Agent）。

可以先运行 Echo Agent 排查网络和 Token：

```bash
npx --yes superhive@latest join \
  --provider echo \
  --server http://192.168.1.20:8787 \
  --name echo-agent \
  --token YOUR_JOIN_TOKEN
```

然后发送 `@echo-agent hello`。

### 状态一直是「结果未知」

说明 Agent 那一轮可能已经做了一部分，但没能确认结局（比如被强制停止、执行中断线、电脑关机）。点开「详情」看具体原因，核对实际做到哪一步后再决定是否重试。

### 如何重置 Agent 会话

在房间里开「新话题」，房间里的 Agent 下一轮都从新会话开始。要彻底清掉某个 Agent 的本机状态：先停止 Agent，再删除本机状态目录 `~/.superhive/agents/` 中对应的状态文件。Server 中的历史消息不会被删除；下一次用同名 Agent 加入时会重新激活身份。
